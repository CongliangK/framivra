## 一、开场钩子（D32/D34/D37/D38/D39）

| # | 规则 | 溯源 |
|---|---|---|
| 1 | **首口播 ≤1.0s**——冷开场不留静默铺垫，留存率优先（用户原话「最前面十七秒没有口播…留存率会好很多」） | D32 |
| 2 | **演示先行**：hook=产品真跑演示（不是标题卡），第一画面即内容 | D32/D34 |
| 3 | **人先说、屏接力演**：真人全屏 7-10s 定调后交棒演示/图表 | D34/D37 复核 |
| 4 | **导航卡→开源卡**：两支柱导航卡带 URL+授权（f≤10 全静止、时长 ≤2 句口播），卡-人-卡时序**句首锁拍**（卡片点亮/文字节拍绑定对口口播句首） | D38 方案B / D39 |

写稿层对应（语料共性，不遵守即显业余）：**钩子先行，无人以自我介绍开场**——第一句完成「这期视频是什么」的定位：替观众说出点开动机 / 目的倒装宣言 / 身份声明+自嘲 / 数字对撞双问句。

## 二、正文论证结构

- **两支柱结构**（如「怎么用 / 怎么做」）：段边界=**冻结预算（帧数）**+ 实录回填漂移规则——预算冻结后口播实测差值只平移段界、不重排段序（D29 T0）。
- **问题链推进**做观点段：现成方案 A？「其实并不行，因为…」→ 方案 B？→ 层层追问到真空白（差评君式）。
- **递进演示链**做产品段：基础功能→下一层能力；每层之间有推进（钩子写法以 `voice-style.md` 为准——锁定稿零反问零悬念钩子，用顺序词过渡）。
- **可信度段必备八件**（缺一即假）：测试条件披露 / 翻车案例现场呈现 / 公开劝退 / 信源实名 / 平衡表述（先承认对立面优点）/ 防杠精确自洽（「注意我没说 A，我说的是 B」）/ 无利益相关一句声明 / 开源承诺具体。
- **语言硬规则**（语料侧结论；**文风层以 `voice-style.md` 为权威**——用户锁定稿实证推翻了本节部分规则：预判抬杠问句/类比公式/「这就完了吗」钩子在锁定稿中均为 0 次，写稿一律按 voice-style.md 执行）：语速标准值 **5.5 字/s**（39 视频实测中位 5.56）；10 分钟片 ≈2800 字（±100，正式定稿前本人试录校准）。
- **出镜连续段 ≤20s**；口播覆盖率 ~95%；真人出镜无额外信息量的长段拆 gfx。
- **明确不抄**：公司化「我们」口吻（个人作者用「我」）、重情绪长升华（全片最多一次、两句以内）、黑话玩梗堆密度、初稿写分镜视觉细节（初稿只留段落级 `[视觉提示]` 一行）。

## 三、演示对位三原则（D35 确立，D36/D37 深化）

1. **无对口口播不留演示**——演示数克制（首期终态全屏演示仅 3 处）；口播未提的画面不留。
2. **D-A 双源策略**：A-roll 视频文件=画面+口播单一事实源——aroll clip 的 `src` 与 voice 事件的 `src` 由同一生成器按同一映射写出处号，**口型同步由构造保证**（不再事后对轨）；撤演示时 aroll 全屏顶替+源内静默谷续延，映射 0 容差断言（D31/D34/D35）。
3. **反哑剧不变量**：全屏 aroll 每帧须被 voice 覆盖，或属 ≤15f 闭嘴拍白名单（0 容差，入 retimeline 硬断言）——杜绝「人对镜头说话无声音」。

附则：演示内动作节拍（按键/行落屏）须随**实录 ASR** 校准，不吃旧时码（D37：旧时码未联动致演示滞后 ~10s）。

## 四、字幕与口播节奏

- **文本权威=锁定稿**；实录差异处采实录；术语白名单；实听误听照实上屏或按白名单改（D31/D35）。
- **句级化规格**（v3.8 拍板）：句级切分、无标点起手、无词中截断、恰 1 条 `\N` 两行、cap_px 1740。
- **时间=ASR 句首真值锚定**（`in=句首−2f`），**禁均匀语速分配**——句内停顿密集段渐进漂移峰值 −130f，七轮刚体平移均未触及，只有句首真值能根治（v3.9）。工具形态=`apps/asr/` 句首锚定链。

## 五、结尾收束（D38/D39）

- **片尾画面必须与同期口播话题一致**——数据卡挂载点须在口播提及相邻话题处，禁止凭空错峰挂卡（详见 §六硬约束）。
- 节奏模板：痛点回顾卡 → 单点数据卡 → 端板**同拍开源句**（URL ≤36f 静止）→ credits 避烧录字幕带。
- 写稿层：收束句 + 互动钩子（具体反馈指令）+（系列化频道）固定签名句——签名句是频道资产。
- **Blender 用户手剪回读协议**（D39）：blend2json 重读→音频拼接→ASR→**用户权威文本对照**→能量谷切点微调；用户手放值须 D-A 恒等修正。

## 六、硬约束（单独成节，违例=返工）

| 约束 | 内容 | 溯源 |
|---|---|---|
| 口播间无缝 | 口播间隙默认零（阅读停顿也不留），仅结构拍（标题卡/端板）例外；执行为**间隙白名单制**，全片仅允许标题拍/端板尾/≤6f 微拍，间隙图入验证门 G5 | D35/D36 |
| 片尾与同期话题一致 | 片尾画面必须与同期口播话题一致；数据卡挂载点=口播提及该话题的相邻语句处 | D38（v3.8） |
| 无对口口播不留演示 | 见 §三-1 | D35 |
| 反哑剧 | 全屏 aroll 每帧被 voice 覆盖或 ≤15f 白名单 | D35 |
| 撤画面必连带审 sfx | 声音无画面=违和；sfx 锚的是画面动作不是时间轴 | v3.5 |
| 口播间隙必有铺底 | 间隙全部 BGM/SFX 接管，不许无声 | D16 |
| 同期声以实录为准 | 念到的才挂，没念的连字幕窗一起删；旧录音多为淘汰稿版本不复活 | D31 用户规则 |
| 概念与实录冲突从实录 | 拆句接力设计因实录连念而废除即先例 | D35 |

## 七、验证门（叙事层）

- **项目门**（`apps/gates/content_gates.py --project-gates`）：G5 间隙图==白名单 / G6 反哑剧 / 首口播时点 / 挂载窗在位 / 字幕规格。
- **三路证据纪律**：①视觉模型只作线索，DOM/像素证据权威（历轮五次应验）；②**能量≠内容**，内容完整性争议升级人耳（D31-f）；③验证/冻结一律以冻结权威副本 timeline.vX-frozen.json 为输入，live 遭并行改写时差异严禁判 FAIL（D39 工程隔离纪律）。
- 修复工作法（迭代纪律）：先问后做不脑测 / 定性走时间轴编排层（Blender=审片界面）/ 区分「编排对实现错」vs「编排本身错」/ 用户权威文本 > 代理回读推断。
