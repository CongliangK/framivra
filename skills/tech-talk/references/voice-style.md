# voice-style · 口播文风规范（文风层权威）

> **本文件是 tech-talk 模板包文风层的权威**：AI 撰写口播初稿时的语气、句式、用词、人称、数字口径一律以本文件为准。叙事结构（开场/论证/演示对位/结尾收束）见 `references/narrative.md`，两层互补不重复。
> **来源声明（决策级约束）**：本规范自 **voice-ime 第 1 期口播锁定稿（v3.2，2026-08-29 用户终决）**逐句实证提炼。该稿经用户 16 项拍板逐字精调，是用户本人说话方式的权威样本——**凡本文件与语料侧结论（`_library/reports/叙事风格分析与稿子方向.md`）冲突处，一律以本文件为准**（用户风格 > 六 UP 主语料公约数，见 §四）。

## ① 文风速查卡（写稿前必读，15 条硬规则）

每条：规则一句 + 正例（取自锁定稿）+ 反例（这样写就偏离了）。

1. **呼吸单位 ≤16 字：小句（逗号之间的单元）平均 ≤16 字，>25 字的小句一段至多一个。**
   ✅「按 Ctrl 加 Alt 加 V，开始说；再按一下，识别完的字直接落在光标上。」
   ❌「按下那个兼具修饰与触发功能的组合键之后系统便会开始采集你的语音并将其转化为文字。」（25+ 字无停顿的欧式长句）
2. **长句 = 2–4 个短小句串联**，用逗号/冒号/破折号接，不写嵌套从句。
   ✅「这个功能默认是关闭的，需要你自己配置开启。」
   ❌「这个虽然默认关闭但只要你愿意就可以通过配置文件开启的功能……」（定语套定语）
3. **全稿只用句号收束：零感叹号、零问号、零反问、零设问。** 不要「为什么？因为……」「你敢信？」「太强了！」。
   ✅「静音超过二点五秒，录音就会自动停止。」
   ❌「那它是怎么做到的？答案就是——」（锁定稿全篇无一处问句）
4. **零语气词：不写「呢/吧/啊/嘛/哦/啦」。** 克制陈述，语速信息密度靠内容不靠语气。
   ✅「至于识别准不准，各家官方都有公开数据，以官方数据为准就好。」
   ❌「这个功能还挺不错的吧？用它打字简直不要太爽哦～」
5. **解释新概念用「X：Y」冒号展开句式，不用「就像/相当于/说人话」类比引导语。**
   ✅「它最新支持了云端大模型后处理：ASR 出来的初稿，可以再交给云端的大模型整理一遍，输出规范的 Markdown。」
   ❌「你可以把它想象成一个私人秘书，帮你把话整理得漂漂亮亮的～」
6. **类比极简、嵌在名词里，全稿 ≤3 处**（胶水层、一等公民这个量级），不展开成段。
   ✅「我做的是胶水：识别和引擎都是别人的开源件」（出自结构总览表「心智模型」列；正文实例=「GNOME 桌面中的一等公民」）
   ❌「这个系统就像一座城市，输入法是公路，模型是发电厂，词库是居民楼，然后……」（连环比喻铺一段）
7. **第一人称「我」直接担纲：我做、我推荐、我喜欢、我没测过。** 不用「笔者」「up 主」，不自我降格也不自夸。
   ✅「目前我最推荐的是 Qwen3-ASR 的 1.7B」「我非常喜欢微信输入法」
   ❌「本 up 主亲测好用到爆」「笔者不才，浅尝辄止地研究了一下」
8. **对观众称「你」，群体场合计「大家」，每段可有且仅有一处「和大家分享」级礼貌用语。**
   ✅「今天我想从两个角度进行分享」「我都感到非常荣幸」→ 锁定稿原文：「能带给你哪怕一点点的帮助，我感到非常荣幸」
   ❌「兄弟们！家人们！咱就是说一整个爱住！」（网络称呼/流行语零容忍）
9. **诚实边界是口头禅：「在我的使用场景中」「没有测过」「不支持」「估计不会太理想」——每个强结论配一处边界或约数。**
   ✅「整个项目我只在 Fedora 加 GNOME 这一套环境里使用……AMD 的显卡没有测过。」
   ❌「这个输入法在任何 Linux 发行版上都能完美运行，吊打一切商业方案。」
10. **数字口径：结论性数据用约数（大约/以上/出头/以内），仅机制讲解用精确数，且精确数全稿个位数。**
    ✅「大约需要 4GB 以上显存，小的 0.6B 有 2GB 出头就能跑」「每一百毫秒会做两件事情」
    ❌「实测占用 4.23GB 显存，识别准确率 97.34%，延迟 0.0612 秒」（营销级伪精确；锁定稿把此类数全移入画面/清单不入口播）
11. **技术名词念法：「Ctrl 加 Alt 加 V」逐键念「加」**；缩写词黑名单管理——LLM 说「大模型」、VAD/预编辑区不出口（进画面标注），首次出现的名词用一句话功能定语带过而非科普段。
    ✅「librime 作为拼音转换内核」「挂在语音链路上的降噪处理」（白名单机制：能点名者点名，余者代称+进画面）
    ❌「接下来我们要讲一下什么是 IBus。IBus（Intelligent Input Bus）是一个输入法总线框架，它的发展历史……」（术语科普腔）
12. **过渡句只用流程顺序词：首先/接下来/再次/至于/最终/下面第二个部分。** 不做悬念钩子、不做「这就完了吗」式递进。
    ✅「接下来，假设进入了开始录音的主分支」「至于语音热键，它走的是另一条路」
    ❌「那么，这就完了吗？当然没有——更刺激的还在后面！」
13. **幽默与自嘲：不用。** 诚实以平铺陈述交付（「这是我个人使用的一个工具，适配的精力有限」），不找包袱。
    ❌「本人技术水平有限，翻车现场惨不忍睹，笑死，根本不带停的。」
14. **段末收束 = 落回能力/事实陈述或行动指引**（怎么用/去哪下/能做什么），不落情绪、不喊口号、不留「下期」钩子（除非拍板）。
    ✅「你可以在评论区提出你的问题，或者在 GitHub 上面提交 issues，我都会进行一个回复。」
    ❌「让我们一起拥抱开源的未来！记得一键三连，下期更精彩！」
15. **零营销腔与零夸张形容词**：不用「颠覆/革命性/极致/丝滑/神器/吊打/秒杀」；评价上限是「稳定、可用」「没有明显的短板」这个量级。
    ✅「在我的使用场景中，它的打字体验也没有明显的短板。」
    ❌「丝滑到飞起，好用到哭，这简直是 Linux 桌面的革命！」

## ② 详细维度分析（附稿例）

### 2.1 句长与节奏
书面单位是长句（句号句均 40.1 字），但**口播呼吸单位是逗号小句（均 11.4 字、中位 11）**。即用户真实的节奏是「短呼吸、慢陈述」：一个完整意思 = 2–4 个 13 字左右的小句，用逗号、冒号、破折号缝合成一句，一个句号落地。约半数小句 ≤10 字，起到强调与停顿作用：
- 「按 Ctrl 加 Alt 加 V，开始说；再按一下，识别完的字直接落在光标上。」（动作段：极短小句连击）
- 「整体上可以分为五个阶段：录音、音频处理、识别、文本规整，最后提交上屏。」（总起句：冒号后顿号列举，列举单元 2–6 字）
- 「假如显存充足，就会选择一点七 B 的大模型；如果显存不充足，就会自动换到零点六 B 的小模型；而如果连小模型都加载失败，就会直接报错提示。」（三分支平铺，条件小句+结果小句，节奏完全对称）

可判定的节奏规则：**小句均长 ≤16 字；>25 字小句一段至多 1 个；连续 3 个以上 >20 字小句即偏离**。破折号用于机制补丁（「你打过的词会被记住、排到前面——两边的候选最终合并成同一个列表」），每段 0–2 处。

### 2.2 用词特征
- **口语化但零口水**：全篇没有语气词、没有「其实/就是说/然后」类的填充词堆叠；口语感来自短小句和直陈动词（「跑」「交给」「丢给」「掐」不用），实际用词偏**书面克制的工程白话**：「整合」「适配」「解耦」「兜底」（兜底只出现在备答节，正文用「应付大多数场景」）。判定：口语感靠句短，不靠语气词。
- **技术名词处理 = 白名单 + 功能定语**：能点名的点名并给一个身份短语（「librime 作为拼音转换内核」「雾凇拼音作为词库」）；点不了名的代称（「云端接好了两家」「默认的本地大模型」），名字进画面。**术语从不展开科普**，IBus/Rime/VAD/LLM 全部移出口播（LLM 说「大模型」）。
- **热键念法固定**：「Ctrl 加 Alt 加 V」，全稿统一，不念「加号」「加 Alt 键的那个」。
- **数字念法**：小数念汉字（「一点七 B」「零点六 B」「二点五秒」）；整数机制数可念（「每一百毫秒」）；约数带量级词（「有几个 G」「4GB 以上」「2GB 出头」「十秒以内」）。

### 2.3 人称与视角
- 「我」50 次承重：做（我做了）、选（我选择了 librime）、荐（我最推荐）、验（我完整验证过）、限（我没有测过）——**「我」永远是判断与责任的落点**。
- 「我们」16 次两类用法：①系统行为叙述（「我们会用一个独立的录音进程开始采集声音」——把机器动作说成「我们」，拉平和观众的共同视角）；②少量包含观众（「我们得先开发出一个输入法」）。**不是公司化的「我们」**（语料侧明令不抄影视飓风此点，锁定稿印证）。
- 「你」27 次，出现在操作指引与条件分支（「如果你没有显卡」「你可以根据自己的需要去调整」）——「你」= 行动指令的目标，不用于调侃对象。
- 「大家」仅 3 次且全在「和大家分享」固定搭配里（开场与收尾）。无「兄弟们/家人们/各位」。

### 2.4 修辞习惯
- **比喻总量 ≤3 处且名词化**：「胶水层」「GNOME 桌面中的一等公民」。心智模型表里的「两扇门」「插座」是制作注释，不入口播正文。**零类比引导语**（就像/相当于/想象成，实测 0 次）。
- **幽默/自嘲：无。** 最接近自嘲的是能力边界陈述「这是我个人使用的一个工具，适配的精力有限」——平铺直叙，不设包袱。
- **反问：零。** 语料侧要求「预判抬杠 ≥3 处」，锁定稿实际用**陈述式预防针**替代：「不过要说明，整个项目我只在 Fedora 加 GNOME 这一套环境里使用」——不用问句也能完成防杠。这是用户风格对语料规则的最大覆盖点。
- **重复与对称**作为强调手段：「它要稳定、可用」「稳定、可用」（D1-V2 同期声复现）；「如果你……就……」三分支平行结构（见 2.1 例）。

### 2.5 段落结构与过渡
- **一段 = 一个点，末句收束能力或行动**：「这两个脚本足以应付大多数场景」「这个热键都能稳定触发」「以官方数据为准就好」——收在「能干什么/去哪里」，不收在情绪。
- **过渡句全部是流程顺序词**（实测）：「今天我想从两个角度进行分享：首先……其次……」「下面第二个部分，我希望分享一下……」「首先，在一切的起点」「接下来，假设进入了……」「再次按下 Ctrl 加 Alt 加 V」「至于语音热键，它走的是另一条路」「识别结果回来之后，就到了文本规整阶段」「最终，所有的结果都处理完之后」。
- **冒号总起句**是用户高频武器：「整个输入链路大概是这样的：」「它主要由以下几个部分组成：」「针对默认的本地模型，我们还支持动态显存管理：」——先给框架再展开。
- 段与段之间靠路线图（开场「今天两件事」）+顺序词导航，**不靠悬念**。

### 2.6 语气基调
- **克制、平视、自信但不越界**：对自己的项目用「稳定、可用」级措辞而非「完美」；对限制主动披露（CPU 路线「速度估计也不会太理想」）。
- **断言都带限定**：「在我的使用场景（当）中」×3、「大多数」×3、「大概」「大约」「估计」各 1–2 次——这不是犹豫，是**把断言责任范围说清**。
- **数字呈现实测口径**：口播只承载结论级数字（约数为主），精确数（延迟/显存/准确率）移入 gfx 图表与组件清单（稿内 C1–C4 图表数据清单即为此机制）。「两个月」「一个夏天」这类时间锚用整数词。
- 对他人成果的措辞克制且给出处：「各家官方都有公开数据，以官方数据为准就好」「最广受大家认可的雾凇拼音」。

### 2.7 禁忌观察（锁定稿从不出现的东西）
1. **感叹号、问号、省略号：0**（正文 76 句全部句号）。
2. **语气词（呢/吧/啊/嘛/哦/啦）：0**。
3. **网络流行语/梗：0**（无「绝了/yyds/拿捏/一整个」类）。
4. **夸张形容词与营销腔：0**（无「颠覆/革命性/极致/丝滑/神器/吊打/秒杀/宝藏」）。
5. **悬念钩子与下期预告：0**（「下期」元素经拍板⑭明删）。
6. **术语科普段：0**（无「什么是 X」式定义段落；定义只用一句身份定语）。
7. **裸精确数字：0**（精确数不入口播，进画面）。
8. **情绪升华：≤1 处、≤2 句**（收尾「能带给你哪怕一点点的帮助，我感到非常荣幸」即满额度）。
9. **公司化「我们」、第三人称自指：「0」**。
10. **连环类比/长比喻段落：0**。

## ③ 初稿自检清单（交稿前逐条对照，任一不满足即返工）

- [ ] 语气词（呢/吧/啊/嘛/哦/啦）= 0

**用词与术语**
- [ ] 无网络流行语、无夸张形容词（对照 §2.7 禁忌词表逐一 grep）
- [ ] 每个技术名词：白名单内点名 + 一句身份定语；白名单外代称、名字进画面
- [ ] 热键统一念「Ctrl 加 Alt 加 V」式写法；小数念汉字（一点七 B）
- [ ] 新概念解释用「X：Y」冒号展开，无「就像/相当于/说人话」引导语
- [ ] 全稿类比 ≤3 处且名词化，无连环比喻

**人称与语气**
- [ ] 「我」承担所有判断与责任落点；「我们」仅用于系统行为叙述；无公司化口吻
- [ ] 观众称「你」（行动指引）与「大家」（≤3 处，且均限「和大家分享」固定搭配）
- [ ] 每个强结论配一处边界限定（在我的使用场景中/没有测过/大多数/估计）
- [ ] 结论性数字用约数；精确数全部移入 gfx/清单，口播 0 裸精确数
- [ ] 情绪升华全稿 ≤1 处、≤2 句

**结构与收尾**
- [ ] 过渡只顺序词（首先/接下来/至于/最终/下面第 N 个部分），无悬念钩子
- [ ] 每段末句收在能力陈述或行动指引，不收情绪、不喊口号
- [ ] 无「下期」元素（除非用户拍板加入）
- [ ] 全稿只有一种终结标点：句号
