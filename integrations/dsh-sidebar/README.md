# Framivra DSH sidebar — read-only preview and stored references

This optional DSH integration lives in `integrations/dsh-sidebar/`, the source home for an external-host adapter, not a native `vtx` app or hook. The Python wheel does **not** include this adapter. Timeline semantics and selection remain exclusively in the unified `vtx` read kernel: this integration does not contain another query/editor/render implementation. It is loaded by DSH, not registered in the native vtx component catalog.

## User flow / limits

Open the Framivra guide card. Enter a **relative timeline file path inside the current Session workspace**, e.g. `timeline.json` or `project/timeline.json`; this never changes the Session working directory. Open/refresh reads capabilities, the complete vtx-emitted document, then all tracks/blocks. Optional integer-frame queries are forwarded to `vtx`; no local interval/track selection algorithm exists. Frame input must be blank (all blocks) or canonical ASCII decimal digits in `0..9007199254740991`, matching the Host token contract: no signs (including `-0`), leading zeros, decimals (`1.0`), exponents (`1e0`) or whitespace. Client checks the exact text and safe bound **before** numeric conversion; lexically invalid or unsafe input shows `BAD_QUERY` without any request and keeps the preview/input for correction. Timeline bounds remain `vtx`'s responsibility (`0 <= frame < duration`, no clipping); a canonical safe integer outside them is forwarded unchanged and surfaces upstream `query.bounds` diagnostics. Each track/block shows all vtx-emitted fields; the complete emitted document and query envelope remain available. Content-version mismatch prevents mixed-version selection display. Incomplete external-subtitle coverage and diagnostics are prominent.

Selecting a track/block reads `vtx reference` with the displayed `content_version` and optional queried integer frame. There is no local ID/range/source-frame inference. Stale reads hide old blocks/raw and require refresh. Raw copying uses the kernel's UTF-8 source substring as a string, never JSON.parse/stringify reconstruction; whitespace, escapes, unknown fields and huge numeric spellings survive. Duplicate keys and oversized output are rejected by the kernel, not silently normalized/truncated. Diagnostic text is bounded to 8 MiB and includes the full schema/version/selection/frame/fps envelope. Clipboard/API refusals are visible and leave the selection available; cancellation never retries or recaptures a draft target. Missing conversation API or an uncreated/blank Session explicitly disables successful draft staging (copy stays usable); the app never creates/retains an extra Session to force a destination.

Only existing `out/final.mp4` and `out/draft_final.mp4` are offered, with **provenance UNKNOWN**. Existence is not evidence of correspondence to this timeline. Playback and query frames are intentionally not synchronized. No rendering, waveform/thumbnail generation, attachment, remote filesystem, external project browsing, timeline writes or editing are implemented. Empty/missing outputs never trigger render. Missing/unsupported installed CLI produces an explicit error; no silent fallback parses the timeline.

## Safety boundary

- Connection Fetch registers exact `/api/framivra/control` (POST) and `/api/framivra/media` (GET/HEAD) routes. The DSH carrier's owner-Peer admission is the authentication boundary; there is no raw WebServer route or standalone service.
- Host chooses Session cwd. Browser gets a 30-minute opaque grant (maximum 32 active) bound to the live Session object and cwd; the media route accepts only Session/grant/opaque-mediaID, never a path. Grants are process-local and disappear on unload.
- `ctx.fs.resolve/contains/stat` enforce canonical containment and regular files. Symlink escape, URL, NUL, traversal, absolute input and cross-session grants are rejected. Local shared-path mapping only; no `node:fs` permission bypass. Every media pull revalidates the grant and output identity/version. A filesystem cannot offer atomic “resolve + run child/open file” through these contracts: concurrent hostile filesystem replacement remains a host-level TOCTOU limitation, not a sandbox guarantee.
- Configure `vtxExecutable` as an administrator-trusted absolute path when outside system PATH. Default `vtx` resolution uses only `/usr/local/bin:/usr/bin:/bin`; custom `trustedPath` entries must all be absolute. Executables resolving inside the Session workspace are rejected. Child argv never uses a shell, cwd is the executable directory (not project cwd), stdin is ignored, safe Python environment clears `PYTHONPATH/PYTHONHOME` and sets `PYTHONDONTWRITEBYTECODE=1` / `PYTHONSAFEPATH=1`. The selected executable/parent directory must itself be trusted; a Python launcher is not accepted instead of installed `vtx`.
- Reads have a 30-second deadline, abort with request cancellation and plugin unload, and cap stdout to 8 MiB. `collected.stdout.readFrom(0).lossy` rejects truncated JSON. Every read, including successful commands, terminates its managed range and awaits **both** direct-result settlement and public `waitForExit()` quiescence before releasing ownership. Cleanup has an independent 5-second bound; an unobservable/stuck range produces `PROCESS_CLEANUP_FAILED`, retains ownership for unload retry, and unload reports failure rather than silently dropping the range. Real 30-second Host deadline testing returned only after cleanup (about 31 seconds). Provider containment limits still apply, including weaker fallback providers' inability to guarantee escaped descendants.
- Complete JSON uses the same native `JSON.parse` source-context codec on Host and Client, preserving numeric tokens with native `JSON.rawJSON` through HTTP, details and serialization. No handwritten JSON parser, network dependency, decimal/BigInt string substitution or second timeline parser is used. Native support is actually probed on each decode; missing support explicitly refuses instead of displaying rounded fields. Frame/index selectors and returned query indices/ranges must remain canonical nonnegative safe integers; vtx-emitted document/extension numeric tokens remain uninterpreted and wire-lossless. This is **not original-source numeric or lexical fidelity**: the current Python upstream already converts decimal/exponent source tokens to float before emitting read/v1 (e.g. source `1.0000000000000001` may emit `1.0`). The sidebar cannot recover that precision. Any “all fields” claim means the vtx-emitted read document only; `content_version` hashes source bytes but does not make the emitted document source-exact. The separate `reference/v1` action now supplies source-exact `document.raw` and selected `raw` strings; it does not change read/v1 preview fields or claim render fidelity. If an installed read/v1 cannot inspect a timeline (for example an unsupported numeric form), preview/open still fails explicitly rather than falling back to another parser. Exit 1/2, schema mismatch and diagnostics are surfaced separately.
- Media is pull-streamed in at most 64 KiB windows using `ctx.fs.readByteRange`. Supports GET, HEAD, one bounded/open/suffix byte Range, 206/416, Content-Length and cancellation. Multiple/malformed ranges fail closed. It does not reuse `/api/file`, buffer whole MP4s, or accept arbitrary filesystem paths.

## Development

Host/source-view tests require Node >=22.15 and native lossless JSON. The SDK/tsdown build uses Node **22.23.3** here (tsdown requires Node ^22.18 or >=24); Python 3 stdlib creates ZIPs. Install this app's declared public-version `devDependencies` in an isolated development environment before running the complete tests; React, ReactDOM, Cordis, ui-slots and jsdom are test/platform suppliers, not plugin runtime copies. Do not assume registry installation currently supplies the candidate SDK API described above. This round used that SDK tarball, copied public Cordis/ui-slots built artifacts and reused already-installed tsdown/React/ReactDOM/jsdom dependencies: **no fresh registry install was tested**.

From the repository root, enter `integrations/dsh-sidebar/` (`cd integrations/dsh-sidebar`), with those build/test dependencies available:

```sh
npm run build:client
npm test
```

Opt-in real integrations (writes only test evidence and isolated fixtures, never changes a user's timeline or live GUI):

```sh
SIDEBAR_DSH_ROOT=/absolute/reviewed/dsh-checkout \
SIDEBAR_REAL_VTX=/absolute/trusted/venv/bin/vtx \
SIDEBAR_EVIDENCE_DIR=/absolute/existing/evidence node --test tests/real-runtime.test.mjs
SIDEBAR_DSH_ROOT=/absolute/reviewed/conversation-draft-checkout \
SIDEBAR_EVIDENCE_DIR=/absolute/existing/evidence node scripts/verify-conversation.mjs
```

Conversation verification requires the supplied checkout's installed dev dependencies; it only writes an evidence-local Vite config/cache, reads that checkout's public-source test assembly and runs this app's test file. It is not a source checkout runtime requirement, CI gate/selection change, DSH source modification or replacement server. Tested conversation candidate: `76f288c3833f5db951087d469b87d3dff69ac2ae`.

The mock CLI returns a fixed envelope; it deliberately does not implement frame/range selection. Security tests exercise URL/NUL/traversal/symlink rejection, Session/expiry/cwd grants, remote mapping, executable hijack, full multi-family original fields, lossy JSON, unsupported CLI, request/unload cancellation, media ID injection, HEAD/Range and pull bounds/revocation. A route-registration test verifies use of authenticated Connection Fetch, **not** real owner authentication.

## Packaging / upstream requirements

The release ZIP must have `package.json`, `cordis.patch.yml`, ESM `lib/index.js`, `lib/client.js`, and `LICENSE` at its root, with no lifecycle scripts, dependencies, node_modules, checkout paths or second React/ReactDOM/Cordis copy. Browser third-party dependencies must be bundled except platform-shared peers. Runtime must work without a DSH source checkout.

The public SDK receives this package directory, `src/client/index.mjs` and an output directory; `package.json.name` is the module ID. `npm run build:client` emits `lib/client.js` and its debug map. React remains a platform-shared request and is declared as an exact `18.3.1` peer (the tested version, not a broader compatibility claim); no other external Client module is emitted. Local JSON presentation code is bundled. The separate packaging command builds again in a fresh staging directory, copies the Host's ESM closure with relative `.js` imports, and strips only the SDK debug-map trailer (the production ZIP omits maps/source paths). It never requires an SDK or source checkout at runtime.

From `integrations/dsh-sidebar/`, with the build dependencies available (**writes a candidate artifact**, not an install):

```sh
npm run package -- --out /absolute/new/framivra-dsh-sidebar-candidate.zip
```

The output must not already exist. The packager allowlists release metadata and omits source scripts/dependencies/node_modules. All stages complete before an atomic, no-overwrite publication of the final ZIP pathname; build/ZIP failure leaves that pathname absent. Hidden staging directories remain beside the output as build evidence. Reusing an existing pathname fails without modifying its bytes. `--client` injection is not supported. The package tests build/load the actual SDK output; no dummy Client ZIP is generated. A successful build/package test does **not** certify clean-profile installation or authentication.

Needed from the read CLI: `vtx -t PATH capabilities|inspect|query`, the `framivra.timeline.read/v1` envelope and exit 0/1/2 as agreed. Reference actions additionally require `vtx -t PATH reference` and `framivra.timeline.reference/v1`; one track/block ID or transient-address selector plus the opened expected content version is passed as bounded argv (`--track-id=…`, `--block-id=…`, `--track-address=…`, `--block-address=…`, `--expected-content-version=…`, optionally integer `--frame`). These `=value` tokens keep leading dashes in IDs from becoming options. Old installed CLIs fail explicitly for reference/copy/stage actions; ordinary read/v1 preview remains independent. Optional query selectors are passed as separate argv tokens (`--family`, `--track-index`, `--block-index`, `--frame` or `--interval`). No subprocess is kept alive between reads.

ZIP installation is being implemented separately in DSH; this app must not claim a one-click install until a clean-profile installation, owner-authenticated preview, uninstall and anonymous-denial smoke actually pass. Live 3080 was neither restarted nor replaced by this slice.
