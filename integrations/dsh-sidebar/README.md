# Framivra DSH sidebar — visual timeline, stored references and explicit semantic edits

This optional DSH integration lives in `integrations/dsh-sidebar/`, the source home for an external-host adapter, not a native `vtx` app or hook. The Python wheel does **not** include this adapter. Timeline semantics and authoritative selection remain exclusively in the unified `vtx` read/edit kernel: this integration compiles UI actions to typed intents, not another semantic editor, query engine, renderer or history store. It is loaded by DSH, not registered in the native vtx component catalog.

## User flow / limits

Open the Framivra guide card. Enter a **relative timeline file path inside the current Session workspace**, e.g. `timeline.json` or `project/timeline.json`; this never changes the Session working directory. Open/refresh reads capabilities, the complete vtx-emitted document, then all tracks/blocks. Optional integer-frame queries are forwarded to `vtx`; no local interval/track selection algorithm exists. Frame input must be blank (all blocks) or canonical ASCII decimal digits in `0..9007199254740991`, matching the Host token contract: no signs (including `-0`), leading zeros, decimals (`1.0`), exponents (`1e0`) or whitespace. Client checks the exact text and safe bound **before** numeric conversion; lexically invalid or unsafe input shows `BAD_QUERY` without any request and keeps the preview/input for correction. Timeline bounds remain `vtx`'s responsibility (`0 <= frame < duration`, no clipping); a canonical safe integer outside them is forwarded unchanged and surfaces upstream `query.bounds` diagnostics. Each track/block shows all vtx-emitted fields; the complete emitted document and query envelope remain available. Content-version mismatch prevents mixed-version selection display. Incomplete external-subtitle coverage and diagnostics are prominent.

### Visual view (read-only unless separately authorized)

The component uses the kernel's complete, same-version inspect + full query projection: frame-query results highlight hits and appear in independent details; they never replace the full view. Video/gfx/audio/subtitle lanes show stored ranges, with display-only subrows for overlapping clips (not extra semantic tracks). The bounded frame window supports zoom, horizontal pan, fit-all, vertical scrolling and keyboard-focusable clips/track selectors. Long labels wrap or ellipsize with full accessible labels/details. Scoped styles live inside the JavaScript factory, with no separate CSS file required by the ZIP.

Click/drag the ruler, use its Arrow/Home/End keys, or step a frame to update the same canonical frame input. Hover is dashed and local; the pinned playhead is separate. Hover, pan and zoom make no requests; moving the playhead does not issue implicit query/render requests. Query/reference actions use the canonical frame at that action's click. Invalid text pauses reference actions rather than reusing a previous frame. Pixel sampling is explicitly approximate (1/1024 CSS px); zoom or integer input is needed for fine/high-frame positions. Unsafe/unprovable duration/range geometry produces `DISPLAY_PRECISION` and retains complete raw/read details instead of rounding. The default ruler is in integer frames, without a locally invented fps/timecode interpretation. Plain visual/keyboard activation or a details selector replaces the selection (track details also clear old blocks). Ctrl/Command-click toggles multi-selection; Shift-click selects the same-kind interval in kernel query order. Visual highlights, manual targets and the **single** reference primary share one selection intent; toggling off the primary selects the last remaining member, or none. Read-only browsing remains usable without semantic-write support. Separate authorization enables the manual controls below; it does not create render results.

Selecting a track/block reads `vtx reference` with the displayed `content_version` and current canonical integer frame. There is no local ID/range/source-frame inference. Stale reads hide old blocks/raw and require refresh. Raw copying uses the kernel's UTF-8 source substring as a string, never JSON.parse/stringify reconstruction; whitespace, escapes, unknown fields and huge numeric spellings survive. Duplicate keys and oversized output are rejected by the kernel, not silently normalized/truncated. Diagnostic text is bounded to 8 MiB and includes the full schema/version/selection/frame/fps envelope. Clipboard/API refusals are visible and leave the selection available; cancellation never retries or recaptures a draft target. Missing conversation API or an uncreated/blank Session explicitly disables successful draft staging (copy stays usable); the app never creates/retains an extra Session to force a destination.

Only existing `out/final.mp4` and `out/draft_final.mp4` are offered, with **provenance UNKNOWN**. Existence is not evidence of correspondence to this timeline. Playback and query frames are intentionally not synchronized. No rendering, waveform/thumbnail generation, attachment, remote filesystem or external project browsing is implemented. Empty/missing outputs never trigger render. Missing/unsupported installed CLI produces an explicit error; no silent fallback parses the timeline.

### Manual editing (writes require explicit authorization)

**Warning: confirmed commits, adopt, undo, status and recover can write the selected project and its persistent core history.** Opening/reading is not write permission. Click the explicit Session/project write button; a separate in-memory server token is required and is revoked on close, cwd/session change, expiry or unload. An old core without advertised bounded `--request-stdin` transport stays read-only; read/copy/no-draft fallback does not depend on write support. Legacy timelines are never silently adopted: the adopt acknowledgement names stable-ID and history changes, and incompatible legacy input is refused without rewriting it.

The Chinese manual panel has dedicated typed forms for all 20 operations: source add/update/remove (explicit cascade); track add/remove/copy/rename/reorder/references; block insert/remove/move/copy/relink/trim/split; parameters update/remove; project resize; and range ripple over explicitly checked tracks. The displayed intent JSON is a read-only review, not an arbitrary transaction editor. Property inputs use the kernel contract's direct-property allowlist. JSON-valued source/property inputs use the same native source-token/rawJSON codec through Host stdin, including nested values: exact unsupported numeric tokens reach the kernel unchanged and are refused, never first rounded by browser JSON.parse. Ordinary `0.1`/`0.5` inputs remain usable. Source windows, audio offsets/loop phase, fade remapping, IDs/references and unknown-field preservation belong only to the kernel plan.

Authorized clips support drag (including same-family cross-track), Ctrl/Command multi-select batch move/copy/delete, inward-only left/right trim handles, and playhead split. A pointer gesture is only an unsaved ghost; pointermove never writes, and pointerup queues one batch. Forms/gestures still require **kernel plan → review frozen request → explicit commit**. All new IDs and the same `op_id`/base/request remain frozen through commit. Selection, frame, typed values, queued operations or authoritative version changes invalidate the old plan; every pending invalidation acknowledgement must complete before replanning, and acknowledgement loss fails closed. A new selection changes only the next operation: already queued explicit intents keep their original targets until cleared. There is no automatic CAS rebase, overwrite or replacement-op retry. Refresh after success re-inspects/re-queries the saved core timeline and restores selection by stable ID. Raw reference actions remain bound to saved frames/version, not the ghost.

Trim is inward-only; gfx trim/split and external subtitle edits are explicitly unsupported. Subtitle split requires duplicate-text or two-text choice. Ripple crossing/fade policies and participating tracks are explicit; there is no implicit AV link. Undo is the actual current-head core transaction, not a browser inverse cache; **redo is unsupported**. Unknown/interrupted commits show the original `op_id`, not “saved” or “failed before writing”. Explicit status/recover and reopen consult core history; the Host has no second publisher, journal or persistent timeline. Revoke, HTTP disconnect and unload terminate and reap owned processes, but cannot promise rollback after a possible commit.

## Safety boundary

- Connection Fetch registers exact `/api/framivra/control` (POST) and `/api/framivra/media` (GET/HEAD) routes. The DSH carrier's owner-Peer admission is the authentication boundary; there is no raw WebServer route or standalone service.
- Host chooses Session cwd. Browser gets a 30-minute opaque grant (maximum 32 active) bound to the live Session object and cwd; the media route accepts only Session/grant/opaque-mediaID, never a path. Grants are process-local and disappear on unload.
- `ctx.fs.resolve/contains/stat` enforce canonical containment and regular files. Symlink escape, URL, NUL, traversal, absolute input and cross-session grants are rejected. Local shared-path mapping only; no `node:fs` permission bypass. Every media pull revalidates the grant and output identity/version. A filesystem cannot offer atomic “resolve + run child/open file” through these contracts: concurrent hostile filesystem replacement remains a host-level TOCTOU limitation, not a sandbox guarantee.
- Configure `vtxExecutable` as an administrator-trusted absolute path when outside system PATH. Default `vtx` resolution uses only `/usr/local/bin:/usr/bin:/bin`; custom `trustedPath` entries must all be absolute. Executables resolving inside the Session workspace are rejected. Child argv never uses a shell, cwd is the executable directory (not project cwd), read stdin is ignored; semantic requests use only public batch `stdio.stdin.data` with official `store [plan] --request-stdin` (8 MiB UTF-8 limit, never `/dev/stdin` reopening or temporary request files); safe Python environment clears `PYTHONPATH/PYTHONHOME` and sets `PYTHONDONTWRITEBYTECODE=1` / `PYTHONSAFEPATH=1`. The selected executable/parent directory must itself be trusted; a Python launcher is not accepted instead of installed `vtx`.
- Reads have a 30-second deadline, abort with request cancellation and plugin unload, and cap stdout to 8 MiB. `collected.stdout.readFrom(0).lossy` rejects truncated JSON. Every read, including successful commands, terminates its managed range and awaits **both** direct-result settlement and public `waitForExit()` quiescence before releasing ownership. Cleanup has an independent 5-second bound; an unobservable/stuck range produces `PROCESS_CLEANUP_FAILED`, retains ownership for unload retry, and unload reports failure rather than silently dropping the range. Real 30-second Host deadline testing returned only after cleanup (about 31 seconds). Provider containment limits still apply, including weaker fallback providers' inability to guarantee escaped descendants.
- Complete JSON uses the same native `JSON.parse` source-context codec on Host and Client, preserving numeric tokens with native `JSON.rawJSON` through HTTP, details and serialization. No handwritten JSON parser, network dependency, decimal/BigInt string substitution or second timeline parser is used. Native support is actually probed on each decode; missing support explicitly refuses instead of displaying rounded fields. Frame/index selectors and returned query indices/ranges must remain canonical nonnegative safe integers; vtx-emitted document/extension numeric tokens remain uninterpreted and wire-lossless. This is **not original-source numeric or lexical fidelity**: the current Python upstream already converts decimal/exponent source tokens to float before emitting read/v1 (e.g. source `1.0000000000000001` may emit `1.0`). The sidebar cannot recover that precision. Any “all fields” claim means the vtx-emitted read document only; `content_version` hashes source bytes but does not make the emitted document source-exact. The separate `reference/v1` action now supplies source-exact `document.raw` and selected `raw` strings; it does not change read/v1 preview fields or claim render fidelity. If an installed read/v1 cannot inspect a timeline (for example an unsupported numeric form), preview/open still fails explicitly rather than falling back to another parser. Exit 1/2, schema mismatch and diagnostics are surfaced separately.
- Media is pull-streamed in at most 64 KiB windows using `ctx.fs.readByteRange`. Supports GET, HEAD, one bounded/open/suffix byte Range, 206/416, Content-Length and cancellation. Multiple/malformed ranges fail closed. It does not reuse `/api/file`, buffer whole MP4s, or accept arbitrary filesystem paths.

## Packaging / upstream requirements

The release ZIP must have `package.json`, `cordis.patch.yml`, ESM `lib/index.js`, `lib/client.js`, and `LICENSE` at its root, with no lifecycle scripts, dependencies, node_modules, checkout paths or second React/ReactDOM/Cordis copy. Browser third-party dependencies must be bundled except platform-shared peers. Runtime must work without a DSH source checkout.

The public SDK receives this package directory, `src/client/index.mjs` and an output directory; `package.json.name` is the module ID. `npm run build:client` emits `lib/client.js` and its debug map. React remains a platform-shared request and is declared as an exact `18.3.1` peer (the tested version, not a broader compatibility claim); no other external Client module is emitted. Local JSON presentation code is bundled. The separate packaging command builds again in a fresh staging directory, copies the Host's ESM closure with relative `.js` imports, and strips only the SDK debug-map trailer (the production ZIP omits maps/source paths). It never requires an SDK or source checkout at runtime.

From `integrations/dsh-sidebar/`, with the build dependencies available (**writes a candidate artifact**, not an install):

```sh
npm run package -- --out /absolute/new/framivra-dsh-sidebar-candidate.zip
```

The output must not already exist. The packager allowlists release metadata and omits source scripts/dependencies/node_modules. All stages complete before an atomic, no-overwrite publication of the final ZIP pathname; build/ZIP failure leaves that pathname absent. Hidden staging directories remain beside the output as build evidence. Reusing an existing pathname fails without modifying its bytes. `--client` injection is not supported. The package tests build/load the actual SDK output; no dummy Client ZIP is generated. A successful build/package test does **not** certify clean-profile installation or authentication.

Manual writes additionally require real `store capabilities` to advertise `request_transport: { stdin: { flag: "--request-stdin", max_bytes: 8388608 } }`, semantic edit operations and the `framivra.timeline.store/v1` envelope. Host passes exactly one lossless JSON request over the public provider's batch stdin; the official CLI enforces strict UTF-8, one JSON value/EOF and its byte bound. No Python bridge, fs writer or fallback to reopening `/dev/stdin` is used. Older installed semantic cores can still supply read/copy but cannot authorize writes through this transport.

Needed from the read CLI: `vtx -t PATH capabilities|inspect|query`, the `framivra.timeline.read/v1` envelope and exit 0/1/2 as agreed. Reference actions additionally require `vtx -t PATH reference` and `framivra.timeline.reference/v1`; one track/block ID or transient-address selector plus the opened expected content version is passed as bounded argv (`--track-id=…`, `--block-id=…`, `--track-address=…`, `--block-address=…`, `--expected-content-version=…`, optionally integer `--frame`). These `=value` tokens keep leading dashes in IDs from becoming options. Old installed CLIs fail explicitly for reference/copy/stage actions; ordinary read/v1 preview remains independent. Optional query selectors are passed as separate argv tokens (`--family`, `--track-index`, `--block-index`, `--frame` or `--interval`). No subprocess is kept alive between reads.

ZIP installation is being implemented separately in DSH; this app must not claim a one-click install until a clean-profile installation, owner-authenticated preview, uninstall and anonymous-denial smoke actually pass. Live 3080 was neither restarted nor replaced by this slice.
