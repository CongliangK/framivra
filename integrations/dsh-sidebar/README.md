# Framivra DSH sidebar — timeline, exact frame drafts and explicit semantic edits

This optional DSH integration lives in `integrations/dsh-sidebar/`, the source home for an external-host adapter, not a native `vtx` app or hook. The Python wheel does **not** include this adapter. Timeline semantics and authoritative selection remain exclusively in the unified `vtx` read/edit kernel: this integration compiles UI actions to typed intents, not another semantic editor, query engine, renderer or history store. It is loaded by DSH, not registered in the native vtx component catalog.

## User flow / limits

Open the Framivra guide card, then **打开时间线** to browse the current Session workspace. Navigate folders or filter the current directory and select a JSON file; only `vtx` decides whether it is a valid timeline. This is a Host-bound file picker, not a browser upload, and it never changes the workspace. Listings expose at most 500 directory/JSON entries, report truncation, and omit resolved links outside the workspace; the public filesystem provider may still enumerate the whole directory internally. If your project is elsewhere, first switch the Session workspace using DSH. **通过路径打开** remains available for a **relative timeline file path inside the current Session workspace**, e.g. `timeline.json` or `project/timeline.json`. Open/refresh reads capabilities, the complete vtx-emitted document, then all tracks/blocks. Optional integer-frame queries are forwarded to `vtx`; no local interval/track selection algorithm exists. Frame input must be blank (all blocks) or canonical ASCII decimal digits in `0..9007199254740991`, matching the Host token contract: no signs (including `-0`), leading zeros, decimals (`1.0`), exponents (`1e0`) or whitespace. Client checks the exact text and safe bound **before** numeric conversion; lexically invalid or unsafe input shows `BAD_QUERY` without any request and keeps the preview/input for correction. Timeline bounds remain `vtx`'s responsibility (`0 <= frame < duration`, no clipping); a canonical safe integer outside them is forwarded unchanged and surfaces upstream `query.bounds` diagnostics. Each track/block shows all vtx-emitted fields; the complete emitted document and query envelope remain available. Content-version mismatch prevents mixed-version selection display. Incomplete external-subtitle coverage and diagnostics are prominent.

### Fixed-frame PNG → current draft (explicit preview-cache write)

Pin an integer global frame, then separately acknowledge **cache/preview-only** write permission and click generate. The Host invokes only the installed core's advertised `frame --frame … --render --include-png --expected-content-version=…`; it never prepares missing inputs, reads `image.path`, substitutes an existing final-video frame, or calls a second renderer. An older core without the actual inline capability fails explicitly; normal read/manual functions remain available. Default frame reads, hovering, selections and stepping do not render. Timeline/history write authorization is separate and does not grant this render consent, or vice versa.

Only a bounded, exact `current-composite`, `approximate:false`, same-saved-version PNG is accepted. FPS matching uses bounded exact rational comparison of the core-emitted source token (including valid `30.0` / `3e1`), not floating-point coercion or object identity. The client checks canonical base64, byte count, PNG/IHDR dimensions, SHA-256, exact document-raw SHA, reference frame/fps, the core identity certificates and a complete browser decode. Limits are 8 MiB for the entire UTF-8 response including envelope/newline, 8192 px per edge and 16,777,216 pixels; DSH's current image policy can be stricter. No resizing, text truncation or lossy reserialization of `reference.document.raw` / selected raw occurs. The frame reference contains core frame-hit selections, not a locally inferred association: a non-hit selected block is refused unless the user explicitly chooses **position-only**, which does not claim that block appears in the image.

After generation, a **second explicit click** either copies the verified PNG or appends its original `File` plus exact reference/certificate text to the current existing draft through the official sequential conversation API (plugin-owned `InputActions` + `ConversationController` `createDrafts`/`releaseDraftAttachment` facade): capture the collapsed selection start synchronously at click time, recheck the saved reference, then append text and image as separate official calls. Existing text, chips and image attachments are retained; a failed or refused later step compensates only the owned image through an authoritative same-identity readback and reports the partial outcome explicitly. There is no send, upload, paste, destination recapture or automatic retry. Selection/frame/version/Session/cwd/close changes and dirty/queued/planned/unknown manual work synchronously invalidate old generated data and cancel pending intake. Actual DSH intake additionally guards revision, composer state, permission, limits, navigation and binding lifetime; a refusal leaves the previous draft unchanged.

Clipboard support/permission refusal is visible and never silently falls back to text. OS clipboard writes cannot be recalled after a later invalidation, and the OS may re-encode PNGs. Temporary decode URLs are revoked; applied draft previews belong to DSH. Certificates identify the render-time inputs with **Fast media stat identity**, not live-atomic media at draft-intake time, a final render, QC or an immutable clipboard byte promise.

### Manual editing (writes require explicit authorization)

**Warning: confirmed commits, adopt, undo, status and recover can write the selected project and its persistent core history.** Opening/reading is not write permission. Click the explicit Session/project write button; a separate in-memory server token is required and is revoked on close, cwd/session change, expiry or unload. An old core without advertised bounded `--request-stdin` transport stays read-only; read/copy/no-draft fallback does not depend on write support. Legacy timelines are never silently adopted: the adopt acknowledgement names stable-ID and history changes, and incompatible legacy input is refused without rewriting it.

The Chinese manual panel has dedicated typed forms for all 20 operations: source add/update/remove (explicit cascade); track add/remove/copy/rename/reorder/references; block insert/remove/move/copy/relink/trim/split; parameters update/remove; project resize; and range ripple over explicitly checked tracks. The displayed intent JSON is a read-only review, not an arbitrary transaction editor. Property inputs use the kernel contract's direct-property allowlist. JSON-valued source/property inputs use the same native source-token/rawJSON codec through Host stdin, including nested values: exact unsupported numeric tokens reach the kernel unchanged and are refused, never first rounded by browser JSON.parse. Ordinary `0.1`/`0.5` inputs remain usable. Source windows, audio offsets/loop phase, fade remapping, IDs/references and unknown-field preservation belong only to the kernel plan.

Authorized clips support drag (including same-family cross-track), Ctrl/Command multi-select batch move/copy/delete, inward-only left/right trim handles, and playhead split. A pointer gesture is only an unsaved ghost; pointermove never writes, and a completed drag queues one batch. Selection/frame/revision or handler-lifecycle changes, pointer cancellation and capture loss cancel the old gesture without queuing it. Its eventual pointer click cannot replace a newer selection; keyboard activation and a fresh pointer sequence remain usable. A harmless press/release still selects normally; completed drag tail clicks do not collapse the multi-selection. Forms/gestures still require **kernel plan → review frozen request → explicit commit**. All new IDs and the same `op_id`/base/request remain frozen through commit. Selection, frame, typed values, queued operations or authoritative version changes invalidate the old plan; every pending invalidation acknowledgement must complete before replanning, and acknowledgement loss fails closed. A new selection changes only the next operation: already queued explicit intents keep their original targets until cleared. There is no automatic CAS rebase, overwrite or replacement-op retry. Refresh after success re-inspects/re-queries the saved core timeline and restores selection by stable ID. Raw reference actions remain bound to saved frames/version, not the ghost.

Trim is inward-only; gfx trim/split and external subtitle edits are explicitly unsupported. Subtitle split requires duplicate-text or two-text choice. Ripple crossing/fade policies and participating tracks are explicit; there is no implicit AV link. Undo is the actual current-head core transaction, not a browser inverse cache; **redo is unsupported**. Unknown/interrupted commits show the original `op_id`, not “saved” or “failed before writing”. Explicit status/recover and reopen consult core history; the Host has no second publisher, journal or persistent timeline. Revoke, HTTP disconnect and unload terminate and reap owned processes, but cannot promise rollback after a possible commit.

### Agent tools → human confirmation → authoritative refresh

The same loaded plugin registers three model tools: `framivra_timeline_read` (inspect/query/source-exact reference), `framivra_timeline_propose` (zero-write semantic plan), and `framivra_proposal_status` (in-memory proposal receipt). Their timeline path is relative to the invoking agent's actual Session workspace. Tools never accept a Session/cwd override, browser grant or write token, and cannot commit, adopt, undo, recover or render. Inspect includes the installed core's edit capabilities; `operation_fields` describes required/optional **top-level keys only**, not value types or a complete schema. Unsupported semantic capabilities do not disable ordinary reads; cleanup failures still fail closed. Project content is untrusted data, not instructions.

A proposal freezes one exact base revision, request, IDs and `op_id`. In the same Session, open that timeline in the sidebar and review **智能体提案**. Explicitly grant project-write permission, clear conflicting manual work, then confirm or reject. Confirmation consumes the original frozen request once through the existing core publisher; it never rewrites its base, generates a replacement request or retries automatically. Successful confirmation re-inspects and re-queries the saved timeline. Manual edits and frame rendering remain mutually exclusive with a live proposal. Selection-driven ordinary reads may coexist with a plan; actual render/store activity and unreaped failed children may not.

A repeated identical pending proposal returns its existing identity; a different live proposal is refused. Cross-Session/cwd/project access is rejected. Unknown outcomes remain blocked until explicit core status/recover and an authoritative read; elapsed time is not recovery, and reconciliation is not proof the original operation applied. Model status and copied UI receipts do not send a message or wake an agent turn: call the status tool on a subsequent turn. Receipts are bounded, process-local observations, not a second journal; after restart, consult core history using the original `op_id`, not an absent receipt. Input JSON strings are limited to 128 KiB and model response text to 256 KiB (UTF-8); oversize results fail without truncation. Source numeric tokens pass through the same lossless codec and bounded kernel stdin. The proposal list's read-only polling never invalidates a frame epoch: only a real dirty/busy/unknown transition aborts an in-flight render or drops a verified PNG.

## Safety boundary

Control requests and responses are bounded at **8 MiB + 64 KiB**, before UTF-8/JSON decoding; diagnostics requests at 16 KiB. Stream byte-brand checks work across loader realms. Child cleanup is scoped to the exact pre-minted grant owner, so cancellation in one Session cannot reap another Session's read. Failed cleanup remains retryable. Optional output directories are skipped without treating them as media, while containment failures still refuse. An in-flight open has an independent 45-second watchdog (Host deadline: 30 seconds), allowing a late minted grant to be explicitly closed after UI cancellation; query/edit activity remains UI-abortable. If transport dies after minting, bounded grant capacity/expiry is the fallback, not a promise of immediate release.

### Host configuration page (administrator-owned, GUI)

The plugin's two fields are served by the Host settings service as a **volatile** namespace (`framivra-readonly`) and appear as a real GUI form on the DSH **Plugins → Framivra** bundle page (slot `plugins.bundle.config`, keyed by package name `framivra-dsh-sidebar`). Values persist in the profile's user layer and apply live without remounting the plugin.

- `vtxExecutable`: the literal `vtx` (resolved through `trustedPath`) or a Host-absolute path. Relative paths are rejected by schema, Host, and the page's own local validation.
- `trustedPath`: colon-separated Host-absolute directories (default `/usr/local/bin:/usr/bin:/bin`); empty or relative segments are rejected.

The page is explicitly an administrator control: preview requests and model tools never modify these values; only the Host administrator sets them on this page, and no grant or write token survives a change. Saving is one atomic mutation pinned to the revision captured when editing started (a later Host-side change can reject the draft, never be silently overwritten by it); a Host rejection keeps the draft, shows the latest Host values, and rebasing onto them is a separate explicit click that never submits by itself. Empty fields submit the documented defaults, never an empty string. **Changing either value immediately invalidates every open preview grant, media route and semantic-write authorization with `CONFIG_CHANGED` (409)** — including in-flight renders, which abort and reap. Cleanup-only operations (`close`, frame `cancel`, write revoke/plan invalidation/cancel) still succeed after a change so stale grants can always be torn down. A new open binds the executable and fingerprint of one consistent configuration snapshot; an invalid live configuration surfaces as `CONFIG_INVALID` and grants stay closed rather than falling back to defaults.

**检查保存的配置** verifies the current saved configuration without a Session or timeline: trusted executable resolution, regular-file/trust checks, actual `read/v1` capabilities and advisory `store/v1` capabilities. It never saves a draft, opens a timeline, grants writes or accepts executable/PATH fields from the browser. Save edited fields first. Results are revision-bound; a configuration change hides an old verdict and requires a new check. Missing executable, unsupported protocol, cancellation and network errors show actionable messages rather than a successful syntax-only check.

CLI/profile patching of the user layer remains a debug substitute only and is not a GUI configuration claim.

- Configure `vtxExecutable` as an administrator-trusted absolute path when outside system PATH. Default `vtx` resolution uses only `/usr/local/bin:/usr/bin:/bin`; custom `trustedPath` entries must all be absolute. Executables resolving inside the Session workspace are rejected. Child argv never uses a shell, cwd is the executable directory (not project cwd), read stdin is ignored; semantic requests use only public batch `stdio.stdin.data` with official `store [plan] --request-stdin` (8 MiB UTF-8 limit, never `/dev/stdin` reopening or temporary request files); safe Python environment clears `PYTHONPATH/PYTHONHOME` and sets `PYTHONDONTWRITEBYTECODE=1` / `PYTHONSAFEPATH=1`. The selected executable/parent directory must itself be trusted; a Python launcher is not accepted instead of installed `vtx`.
- Reads have a 30-second deadline, abort with request cancellation and plugin unload, and cap stdout to 8 MiB. `collected.stdout.readFrom(0).lossy` rejects truncated JSON. Every read, including successful commands, terminates its managed range and awaits **both** direct-result settlement and public `waitForExit()` quiescence before releasing ownership. Cleanup has an independent 5-second bound; an unobservable/stuck range produces `PROCESS_CLEANUP_FAILED`, retains ownership for unload retry, and unload reports failure rather than silently dropping the range. Real 30-second Host deadline testing returned only after cleanup (about 31 seconds). Provider containment limits still apply, including weaker fallback providers' inability to guarantee escaped descendants.
- Complete JSON uses the same native `JSON.parse` source-context codec on Host and Client, preserving numeric tokens with native `JSON.rawJSON` through HTTP, details and serialization. No handwritten JSON parser, network dependency, decimal/BigInt string substitution or second timeline parser is used. Native support is actually probed on each decode; missing support explicitly refuses instead of displaying rounded fields. Frame/index selectors and returned query indices/ranges must remain canonical nonnegative safe integers; vtx-emitted document/extension numeric tokens remain uninterpreted and wire-lossless. This is **not original-source numeric or lexical fidelity**: the current Python upstream already converts decimal/exponent source tokens to float before emitting read/v1 (e.g. source `1.0000000000000001` may emit `1.0`). The sidebar cannot recover that precision. Any “all fields” claim means the vtx-emitted read document only; `content_version` hashes source bytes but does not make the emitted document source-exact. The separate `reference/v1` action now supplies source-exact `document.raw` and selected `raw` strings; it does not change read/v1 preview fields or claim render fidelity. If an installed read/v1 cannot inspect a timeline (for example an unsupported numeric form), preview/open still fails explicitly rather than falling back to another parser. Exit 1/2, schema mismatch and diagnostics are surfaced separately.
- Media is pull-streamed in at most 64 KiB windows using `ctx.fs.readByteRange`. Supports GET, HEAD, one bounded/open/suffix byte Range, 206/416, Content-Length and cancellation. Multiple/malformed ranges fail closed. It does not reuse `/api/file`, buffer whole MP4s, or accept arbitrary filesystem paths.

## Packaging / upstream requirements

The release ZIP must have `package.json`, `cordis.patch.yml`, ESM `lib/index.js`, `lib/client.js`, and `LICENSE` at its root, with no lifecycle scripts, dependencies, node_modules, checkout paths or second React/ReactDOM/Cordis copy. Browser third-party dependencies must be bundled except platform-shared peers. Runtime must work without a DSH source checkout.

The own builder receives this package directory, `src/client/index.mjs` and an output directory; `package.json.name` is the module ID. `npm run build:client` emits `lib/client.js` and its debug map. React remains a platform-shared request and is declared as an exact `18.3.1` peer (the tested version, not a broader compatibility claim); no other external Client module is emitted unless explicitly declared in `dsh.client.external`. Local JSON presentation code is bundled. The separate packaging command builds again in a fresh staging directory, copies the Host's ESM closure with relative `.js` imports, and strips the debug-map trailer (the production ZIP omits maps/source paths). It never requires a DSH SDK package or source checkout at runtime.

From `integrations/dsh-sidebar/`, with the build dependencies available (**writes a candidate artifact**, not an install):

```sh
npm run package -- --out /absolute/new/framivra-dsh-sidebar-candidate.zip
```

The output must not already exist. The packager allowlists release metadata and omits source scripts/dependencies/node_modules. All stages complete before an atomic, no-overwrite publication of the final ZIP pathname; build/ZIP failure leaves that pathname absent. Hidden staging directories remain beside the output as build evidence. Reusing an existing pathname fails without modifying its bytes. `--client` injection is not supported. The package tests build/load the actual SDK output; no dummy Client ZIP is generated. A successful build/package test does **not** certify clean-profile installation or authentication.

Manual writes additionally require real `store capabilities` to advertise `request_transport: { stdin: { flag: "--request-stdin", max_bytes: 8388608 } }`, semantic edit operations and the `framivra.timeline.store/v1` envelope. Host passes exactly one lossless JSON request over the public provider's batch stdin; the official CLI enforces strict UTF-8, one JSON value/EOF and its byte bound. No Python bridge, fs writer or fallback to reopening `/dev/stdin` is used. Older installed semantic cores can still supply read/copy but cannot authorize writes through this transport.

Needed from the read CLI: `vtx -t PATH capabilities|inspect|query`, the `framivra.timeline.read/v1` envelope and exit 0/1/2 as agreed. Reference actions additionally require `vtx -t PATH reference` and `framivra.timeline.reference/v1`; one track/block ID or transient-address selector plus the opened expected content version is passed as bounded argv (`--track-id=…`, `--block-id=…`, `--track-address=…`, `--block-address=…`, `--expected-content-version=…`, optionally integer `--frame`). These `=value` tokens keep leading dashes in IDs from becoming options. Old installed CLIs fail explicitly for reference/copy/stage actions; ordinary read/v1 preview remains independent. Optional query selectors are passed as separate argv tokens (`--family`, `--track-index`, `--block-index`, `--frame` or `--interval`). No subprocess is kept alive between reads.

## Install (official local-directory flow)

Delivery is a release ZIP, installed by **extract → official local-directory plugin install** (not a native ZIP upload): verify the ZIP's SHA-256, extract it to a fresh directory of your choice, then install that directory into the intended profile with the official `dsh plugin` management command (forwarded to `pnpm`; have `pnpm` available for this command only):

```sh
unzip framivra-dsh-sidebar-candidate.zip -d /absolute/new/framivra-dsh-sidebar
dsh plugin --profile web add file:/absolute/new/framivra-dsh-sidebar
```

`--profile web` matches the GUI web profile shown by `dsh web`; substitute the profile you boot. DSH records any installed package exporting a `dsh.bundle` layer and checks `engines.dsh` at installation. In the bundle's configuration page, set the trusted installed `vtx` executable outside the Session workspace; no source checkout or manual YAML edit is required at runtime. Clean-profile installation, owner-authenticated preview, anonymous denial, persistence/restart and uninstall remain artifact-specific acceptance obligations. The official visual-workbench acceptance above records the checks actually run for its exact ZIP SHA-256; it does not imply the listed UNRUN checks passed. The development instance is isolated from live 3080; switching that live instance requires separate approval.
