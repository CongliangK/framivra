# 在 DSH 中制作视频

查看时间线、按 `mm:ss:frame` 时间码或整数帧定位，在同一监视器切换固定帧预览、已有成片和可选的音画窗口；可信固定帧和选区可加入会话草稿，直接剪辑松手即保存。

## 可视化安装（推荐）

适配 **DSH 0.2.2-rc.1 / Node ≥24.9.0**。通过 npm 安装的 DSH 还需 `pnpm` 在宿主 PATH 中可用，准备命令见下方「命令行安装」。已安装 DSH 的用户优先在界面中从 npm 安装：

1. 打开 DSH 的 **插件** 页，点击 **添加插件**。
2. 在包名输入框中填写 `framivra-dsh-sidebar`，无需下载 ZIP、手动解压或克隆仓库。
3. **安装源** 可保留界面默认值（如中国大陆镜像源）；若找不到包或版本未同步，切换到 npm 官方源（`https://registry.npmjs.org/`）。
4. 确认来源可信后点击 **安装**（**下载插件及依赖，并写入当前 profile**）；插件会以你的本机权限运行，仅安装信任的来源。
5. 安装完成后刷新页面；若界面提示需要重启或出现宿主构建不匹配，重启当前 DSH 后再刷新。进入 **插件 → Framivra**，按下方「首次配置与使用」完成内核连接。

npm 包仅提供侧栏，不包含 Python `vtx` 内核、FFmpeg、浏览器或模型；内核与媒体依赖需另行准备。

## 命令行安装（可选）

供智能体或终端用户使用；普通用户优先使用上方界面。尚未安装 DSH/pnpm 时执行（**全局安装写操作**；已有兼容版本可跳过）：

```bash
npm install -g @deepseek-ai/dsh@0.2.2-rc.1 pnpm
```

再从 npm 官方仓库安装插件（**下载插件及依赖，并写入所选 profile**）：

```bash
dsh plugin --profile web add framivra-dsh-sidebar --registry=https://registry.npmjs.org/
```

`web` 对应 `dsh web`；使用其他 Web profile 时，将 `web` 替换为实际启动的 profile 名。插件须通过 DSH 界面或上述命令装入目标 profile；仅执行 `npm install -g framivra-dsh-sidebar` 不会让 DSH 加载它。

安装后启动或重启使用该 profile 的 DSH（Web profile 用 `dsh web`），刷新页面，再按下方说明配置内核。

## 首次配置与使用

先按[三平台一键安装](<../README.md#一键安装完整非-ai-环境>)准备非 AI/CDP 制作环境；在插件配置页 **扫描已有安装 → 选择登记环境 → 保存配置 → 检查连接**。然后回到会话，打开右侧 **Framivra** 并选择时间线。

- **内核**：优先发现统一安装根中的登记文件，展示实际源码提交和配置；扫描只读、不执行程序、不搬迁旧内核。登记不代表协议兼容，保存后仍检查实际能力。Windows 选择原生绝对 `vtx.exe`，不把分号 PATH 填入现有 POSIX 受信 PATH 字段。可信本地 wheel 安装仍保留为高级 POSIX 选项，不是完整源码/媒体安装。
- **配置文件**：常用字段表单与完整 JSON 编辑；全局缓存三选一：`off` 不读取或保留可复用缓存（临时件用后清理）、`core` 压缩保留高价值 gfx、合成缓存短暂（缺省/推荐）、`aggressive` 保留更多缓存。缺失字段只显示推荐值，不自动写回；确认保存会影响使用同一 `VTX_CONFIG` 的所有工程，下次操作读取生效，不改变运行中任务、不立即清理旧目录。保存前比较内容，保留备份并检查冲突。
- **空间与缓存**：打开时间线后，在属性侧栏查看项目、cache、out 与其他文件的逻辑占用；可见时每 10 秒采样。清理先预演候选，再单独确认所有写入者已停止；不提供一键清空，失败或结果未知时先核查、重新预演。旧内核只禁用这项功能。边界见[空间接口](https://github.com/CongliangK/framivra/blob/main/docs/reference/storage-api.md)。
- **工程属性**：在「属性与编辑」查看已保存帧率、画布和选区信息。复杂修改请在会话里描述；完成后点顶栏「刷新保存版本」查看结果。
- **检查**：分别核对读取、完整帧合成及语义编辑的能力；不是渲染验收，也不授予写权限。Windows 支持浏览、精确定位、文本引用和成片播放，不提供完整帧生成或连续音画预览。仅当安装的内核声明原生 Windows 事务能力时，才可显式授权语义编辑。[内核 `vtx store`](https://github.com/CongliangK/framivra/blob/main/docs/reference/timeline-api.md#发布与恢复协议)在每次操作时检查直接本地固定 NTFS 资格；连接检查和授权不验证工程的卷或 ACL。只在可信私有目录中启用，替换文件及历史将继承目录 ACL，不保留独立文件 ACL。侧栏模型工具始终只读。不能把已有成片当作当前时间线的合成证据。

监视器的「固定帧预览 / 音画窗口 / 成片渲染」与时间线、时间码共用整数播放头。拖动或输入时间码会暂停并定位成片，成片播放/原生定位也回传播放头；位置联动不证明成片对应当前保存版本，仍标记来源 UNKNOWN，无成片不会自动整片渲染。NTSC 时间码采用名义 non-drop 计数，不是墙钟；媒体秒按精确有理帧率换算，高级全局帧入口保留。时间线工具栏的「轨道高度」可手动调节或「适配全部轨道」；空间不足时可先打开「轨道专注视图」，这些操作不改工程。

在顶栏或拖动提示中点 **启用编辑** 后，拖动片段或向内拖动边缘，松手即保存；非法重叠等操作会被拒绝，原片段不动。磁铁按钮切换**吸附**，拖动时按住 Alt 可临时关闭。点击两段之间的 **↔** 闭合同轨空隙，只移动该轨后续片段，不缩短工程。分割在播放头处保存；移除须明确确认。需要回退时可用时间线工具栏**单步撤销**；旧工程的显式接管、版本状态与恢复在顶栏「历史与恢复」。

实时模式打开画面下方的「预览生成设置」图标，先勾选「允许写入预览缓存（不改时间线）」，再单次「显式生成并验证固定帧 PNG」，或另勾「随播放头实时生成（写预览缓存）」启用跟随。后者停顿后才生成最新帧，每次仍完整验证 core 原文/版本与 PNG，失败停止、不自动重试；取消等待实际回收，不以旧图冒充当前帧。PNG 无音频；新版内核可无声预览仅以官方 BGM 引用为扩展的工程，不执行该插件，其他生效插件仍拒绝。PNG 不承诺视频帧率播放，不替代完整 `all` 与音频/QC。

缺图形缓存时，另勾「允许按需准备当前帧图形」，可见 HTML 还须单独信任已保存页面/脚本。普通媒体、透明图形和字幕仍按内核顺序完整合成，只准备请求帧，不是单页截图或整片渲染。HTML 不是沙箱，仅用于检查过的可信工程。

扫描不执行程序；安装与保存需明确确认。预览许可、冷准备与 HTML 信任和剪辑授权分开；排队包含在原 30 秒预算内，可显式取消，不自动重试。冷准备临时文件在响应前清理，图片与引用须显式点击才进入草稿，不发送。每次最多追加 300 字符的路径、对象和帧范围摘要，不插入原始 JSON；已有文字和附件不替换。

## 音画窗口（Linux，默认关闭）

npm 侧栏不带固定 wheel 或启动器，也不会为你下载、安装或发现它们。没有单独配置且通过资格检查的启动器时，仍可按原有平台能力浏览、生成固定帧或播放已有成片；macOS 和 Windows 不开放音画窗口。

1. 维护者先核对独立可信来源提供的 wheel SHA-256。用匹配版本的内核发布源中的 `scripts/preview_window_wheel.py` 作 `vtx-preview` 启动器，在工程和所有 Session 工作区之外准备一个仅 Host 用户可访问的物理目录（`0700`，不是符号链接）。将已核对的 wheel 放为 `kernel.whl`，将可信摘要写为 `kernel.sha256`（单行小写 64 位十六进制，末尾换行）。不要从工程或未知来源选启动器，也不要把普通 `vtx` 当作启动器。
2. 以非 root Host 用户使用该启动器，从同一个可信 wheel 独立安装后的物理 `site-packages` 显式创建并核对隔离投影。第一条会写入档案目录的 `runtime`；第二条只核对固定身份：

   ```sh
   env -u VTX_CONFIG /absolute/host-profile/vtx-preview --stage-from /absolute/wheel-venv/lib/python3.X/site-packages
   env -u VTX_CONFIG /absolute/host-profile/vtx-preview --verify
   ```

3. 关闭要配置的**独立 DSH 实例**。在该实例的 `$DSH_HOME/profiles/<profile>/cordis.patch.yml` 的 YAML 列表中，按插件条目 ID 添加或合并以下配置（只写独立实例；路径为占位符）。侧栏自定义配置页不提供此字段，不要修改项目配置或已安装包的清单：

   ```yaml
   - id: framivra-readonly
     config:
       previewWindowExecutable: /absolute/host-profile/vtx-preview
   ```

   路径须为实际的绝对物理路径；省略或使用空字符串即关闭，不要替换单独的 `vtxExecutable`。启动同一独立 profile 后重新打开时间线，只有 Host 核验实际启动器和能力后才显示 **音画窗口**。更新 wheel 时重新验收新的独立档案，不用原地替换已固定的身份。

- 手动窗口每次都须明确允许写入预览缓存与按需冷准备。自动跟随还须对当前会话和工程单独授权（最多 10 分钟、120 窗，且不得超过打开授权）；停止、撤销或到期不会自动续期。窗外定位须等旧作业确认回收；窗内定位也只有在原请求完整验证、目标帧定位并解码后才显示。
- **默认不授权续窗，也不读取归档。** 续窗须启动器支持、单独勾选，并从浏览器原生播放开始；最多持有当前窗和一个相邻窗。后继没就绪时音画一起等，不承诺无缝。已核归档 A/V 须启动器另行通过核验、先停止自动预览，然后点选一个获批准的精确帧；不会自动查找、预取或写入归档。
- 只支持启动器实际宣告和核验的素材能力。暖 SVG、整片音频基准混音和临时首图均须独立许可，不能假定任意内核支持，也不是通用 HTML 或插件渲染。临时首图不是音画就绪，也不能复制或进入草稿；状态带只反映本次持有且浏览器可播的已验证窗口，不是整个工程的缓存清单。窗口和归档均不证明当前输入的原子新鲜性、正式成片或 QC，也不授予编辑权。
