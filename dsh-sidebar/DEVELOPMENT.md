This optional DSH integration lives in `dsh-sidebar/`, the source home for an external-host adapter, not a native `vtx` app or hook. The Python wheel does **not** include this adapter. Timeline semantics and authoritative selection remain exclusively in the unified `vtx` read/edit kernel: this integration compiles UI actions to typed intents, not another semantic editor, query engine, renderer or history store. It is loaded by DSH, not registered in the native vtx component catalog.

## Implementation and evidence boundaries

The current target is **unmodified npm DSH `0.2.2-rc.1`**, plugin version `0.3.0`. This is the installed prerelease, **not a compatibility claim for a future stable `0.2.2`**. The adapter requires no DSH source modification, no Host edits, no installer extension and no `@deepseek-ai/dsh-client-modules/build` dependency: its own builder uses the public `tsdown` API. The Host checks the selected installed core's actual capabilities; prior supplier identities remain attached to their historical acceptance below. Engines: Node `>=24.9.0`, DSH exactly `0.2.2-rc.1`; five client-bundle injection declarations. Cordis `4.1.0` and Schemastery `3.19.0` match the tested SDK. Published `dsh-client-ui-slots` remains a development/test supplier; it is not a standalone client-bundle injection.

The conversation-draft bridge uses official `InputActions` plus public `ConversationController` methods. `createDrafts(sessionId, files, false)` explicitly disables service-owned image uploads. The Guide retains the **tab-scoped boolean** `replaceTab: true`; the separate controller-level API takes a TabId. The builder rejects undeclared DSH/React-family runtime imports before resolution, even when a development dependency could otherwise be silently inlined. The release includes exported English/Chinese metadata and an SVG icon.

Evidence remains supplier- and artifact-specific. Acceptance sections dated before this upgrade are preserved historical evidence for their original DSH and ZIP, **not certificates for the current release**. Agent-loop fixtures use a clearly labelled deterministic scripted model, not an external AI service or billing account.

### Isolated fixed-wheel program audio

Only the trusted direct Linux fixed-wheel launcher can advertise `capabilities.capabilities.preview_window.program_audio:true` for an owner open. Ordinary vtx/model capabilities cannot claim it. The Host adds `previewSession.programAudioContinuation:{version:1}` only when that same qualified launcher advertises exact `input_epoch:true` and `program_audio:true` and the owner open supports `previewSession.continuation:{version:1}`. Clients without this integration keep the two options mutually exclusive.

`POST /api/framivra/control` `authorize-preview-session` accepts optional exact `useProgramAudio:true` alongside `scope:'current-project'`, `renderConsent:'cache/preview-only'` and `prepareInputs:true`. For combined use, that same lease must also explicitly request and echo `continuation:true`. Independently authorized `readWarmSvg:true` may coexist; `firstFrame` may not. `POST /api/framivra/window` `session-render` and `session-continue` require `useProgramAudio:true` **iff** the exact original `sessionId`, `grant`, `previewGrant` and `ownerId` lease carries it; otherwise the field must be absent. Manual windows, archive reads, provisional pictures and cancellation never accept it. Host appends the existing `--use-program-audio` after `--render --include-media --prepare-inputs` and optional `--read-warm-svg` for a qualified hit. No new process route, budget, retry, expiry or cleanup authority is granted. The bounded short-project operation mixes current inputs in its private workspace, not a past formal output or saved snapshot; refusal never falls back to a different audio mode.

A successful `preview-window/v1` receipt must contain `program_audio:true` iff requested (absent otherwise). The Host validates its pinned wheel profile, saved version, interval and inline bytes before relaying. This mode alone carries `X-Framivra-Program-Audio: 1` and always requires a valid `X-Framivra-Input-Epoch` (the launcher’s opaque program-domain SHA-256). A successor needs a fresh nonce and the same lease, saved version, epoch and exact adjacent start after explicit reap confirmation of its original predecessor. The new receipt must reproduce that epoch, including any warm SVG input identity; if it differs, no handoff or fallback. The browser independently matches the mode, epoch and `X-Framivra-Continuation-From` (absent on a foreground window, exact predecessor on a successor), and rejects archive markers on live windows. Only native Play starts preparation of a successor; at most the current window and one successor may be held. These checks do not confer formal audio, QC, cache or archive approval. Packaged wheel/Host and real GUI acceptance: **UNRUN**.

### Isolated fixed-wheel provisional visual

Host support is default-off for each owner preview Session. Open advertises `capabilities.capabilities.preview_window.first_frame:{version:1}` and `previewSession.firstFrame:{version:1}` only after `[launcher, '--first-frame-capabilities']` independently verifies the configured Linux fixed-wheel profile and public stdout/settlement transport. Ordinary vtx and the old fixed-wheel window capability cannot claim it. The extra probe has a 3 s budget and is skipped if the open lacks time for that probe and cleanup. An unsupported or timed-out but reaped probe leaves ordinary window qualification intact; unconfirmed reaping still fails closed. The owner's `authorize-preview-session` must explicitly add `firstFrame:true` alongside the existing `current-project`, `cache/preview-only` and `prepareInputs:true` permissions; the resulting lease echoes `firstFrame:true`. It cannot be combined with warm SVG reads or continuation on that lease.

- Normal `POST /api/framivra/window` `session-render` accepts optional `firstFrame:true` only with this lease. It selects the dedicated `timeline preview-window-first-frame` producer, not both producers, under the original request/owner/timeout. The Host drains the raw public stdout pipe and binds both framed receipts to a fresh 128-bit nonce, fixed profile, saved content and exact frame/range. It checks bounded RGB8 PNG structure, CRC, bounded inflation and actual SHA-256 before exposing any bytes. Stderr is not exposed.
- `POST /api/framivra/window` with `op:'session-first-frame'` requires the original `sessionId`, `grant`, `previewGrant`, `ownerId`, `operationId`, `contentVersion` and `frame`, plus exclusive integer `end` and `project` (exact Session-relative timeline path from the lease). Polling does not spawn or spend another window. It returns an empty, no-store `204` if the tuple has no available current image, or a no-store `200 image/png` with `Content-Length` and `X-Framivra-Version`, `-Start`, `-End`, `-SHA256` (bare lowercase digest). Unauthorized or stale requests may fail. The image belongs only to the live operation: never a path, history, draft attachment, input-epoch proof, audio/video readiness, or final output. Public filesystem and grant checks can cut off observed staleness; they are not an atomic freshness guarantee. A client must discard the visual on original completion/failure, cancellation, or binding change.
- The original HTTP response remains terminal `video/mp4` (or normal failure). Only matching `F → W`, complete EOF, normal exit and confirmed SDK managed-range reaping can replace the provisional visual with the existing audio/video response. The Host clears the single temporary PNG on success or failure; revocation, cancellation and observed staleness cut it off without releasing the producer early. No mixed/unfinished media response, background continuation or production enablement. Host mocks and official UI runtime for this change: **UNRUN** in this static implementation round.

### Approved formal archive A/V

An isolated Linux fixed wheel may separately qualify with `--formal-archive-capabilities` (no project argument). Its exact `framivra.preview-formal-archive.capabilities/v1` response is `{schema,available:true,launcher,wheel_sha256,runtime_projection_sha256}` and must match the installed window profile. Only that owner open advertises both `preview_window.formal_archive:{version:1}` and `previewSession.formalArchive:{version:1}`. No existing read, fixed-frame, live window, media or automatic-preview grant implies archive authority.

`POST /api/framivra/window` `formal-archive-read` accepts only `sessionId`, `grant` (the original owner open grant), `ownerId`, fresh `operationId`, `contentVersion`, and integer `frame`. One explicit click uses the same preview admission and managed process settlement, with no queue, live render, write, retry, polling or prefetch. Stop automatic preview first. Exact `formal-archive-cancel` uses the same owner/open/operation tuple (no frame/version); its `{ok:true,reaped:true,operationId,ownerId,openGrant}` confirms that no child remains. No caller or receipt chooses a media path.

The Host checks the saved version before and after the command. It passes only `-t <trusted-current-path> timeline preview-formal-archive --frame N --expected-content-version=sha256:… --read-approved-archive --nonce=<32hex>`. The independently configured launcher must find exactly the approved point and verify all current ordinary project source bytes against the independently reviewed archive. The Host accepts only the exact `framivra.preview-formal-archive/v1` success schema: `{schema,ok:true,nonce,content_version,start,end,fps:{num,den},width:1920,height:1080,audio_sample_rate:48000,audio_channels:2,mime:'video/mp4',sha256,byte_length,base64,manifest_sha256,launcher,wheel_sha256,runtime_projection_sha256}`. Digests other than `content_version` are bare lowercase SHA-256. It verifies pinned identity, nonce, current FPS, exact start, in-project end, at most four seconds, canonical inline bytes/digest and limits (5 MiB MP4, 8 MiB stdout); only settled bytes are relayed.

Only a normal exit `1` with one compact LF-terminated `{schema,ok:false,nonce,code}` on stdout, the same archive schema and request nonce, and confirmed managed-range cleanup can produce an archive `409`. The fixed codes map as follows:

| Fixed-wheel code | Host error | Meaning |
|---|---|---|
| `archive.selector_mismatch` | `ARCHIVE_SELECTOR_MISMATCH` | The project path, exact start or saved version does not match the approval; the receipt does not identify which. |
| `archive.inputs_mismatch` | `ARCHIVE_INPUTS_MISMATCH` | The declared project inputs could not be verified against the approval; this is not proof of a change. |
| `archive.unavailable` | `ARCHIVE_UNAVAILABLE` | The approval, media or fixed-wheel deployment could not be verified; this is not a claim that the archive is absent. |

Other exit/signal combinations, malformed receipts or unconfirmed cleanup do not acquire these codes. Failures never carry media or raw launcher diagnostics. Ordinary `preview-window/v1` is unchanged. The browser uses its own Chinese text for these three conflicts and preserves it through the cleanup acknowledgement.

The browser verifies the binary HTTP receipt (`X-Framivra-Media-Kind: approved-formal-archive/v1`, operation ID, version, range, FPS, required length and SHA-256). It plays via native controls on the existing monitor video element, with **已核归档 A/V [start, end)** and no autoplay, continuation, input epoch, live coverage, draft or copy authority. Invalidations withdraw the video and revoke its URL. This is playback of a checked archive, not atomic source freshness, a current render, cache coverage, a new approval or final QC. The opt-in real-runtime case takes `SIDEBAR_PREVIEW_WINDOW_EXECUTABLE`, `SIDEBAR_FORMAL_ARCHIVE_TIMELINE`, `SIDEBAR_FORMAL_ARCHIVE_FRAME`, and independently recorded `SIDEBAR_FORMAL_ARCHIVE_SHA256`; it does not take an archive path. Independently staged launcher / official GUI acceptance: **UNRUN** in this static round.

## User flow / limits

Open the Framivra guide card, then **打开时间线** to browse the current Session workspace. Navigate folders or filter the current directory and select a JSON file; only `vtx` decides whether it is a valid timeline. This is a Host-bound file picker, not a browser upload, and it never changes the workspace. Listings expose at most 500 directory/JSON entries, report truncation, and omit resolved links outside the workspace; the public filesystem provider may still enumerate the whole directory internally. If your project is elsewhere, first switch the Session workspace using DSH. **通过路径打开** remains available for a **relative timeline file path inside the current Session workspace**, e.g. `timeline.json` or `project/timeline.json`. Open/refresh reads capabilities, the complete vtx-emitted document, then all tracks/blocks. Optional integer-frame queries are forwarded to `vtx`; no local interval/track selection algorithm exists. Frame input must be blank (all blocks) or canonical ASCII decimal digits in `0..9007199254740991`, matching the Host token contract: no signs (including `-0`), leading zeros, decimals (`1.0`), exponents (`1e0`) or whitespace. Client checks the exact text and safe bound **before** numeric conversion; lexically invalid or unsafe input shows `BAD_QUERY` without any request and keeps the preview/input for correction. Timeline bounds remain `vtx`'s responsibility (`0 <= frame < duration`, no clipping); a canonical safe integer outside them is forwarded unchanged and surfaces upstream `query.bounds` diagnostics. Each track/block shows all vtx-emitted fields; the complete emitted document and query envelope remain available. Content-version mismatch prevents mixed-version selection display. Incomplete external-subtitle coverage and diagnostics are prominent.

### Fixed-frame PNG → current draft (explicit preview-cache write)

Pin an integer global frame, separately acknowledge **cache/preview-only** write permission, then click generate or explicitly enable **随播放头实时生成（写预览缓存）**. Follow debounces changes for 120 ms and serializes the latest still-current frame intent through the same complete core PNG/reference verification; it is not video-rate playback and the PNG has no audio. Failure stops follow without automatic retry. Invalidation removes the old image immediately; an aborted request must finish explicit Host cancellation/reaping before the next request can start. Unconfirmed cleanup blocks further rendering until explicit cancellation confirms release. The Host invokes only the installed core's advertised `frame --frame … --render --include-png --expected-content-version=…`, with cold preparation only under the additional consent below; it never reads `image.path`, substitutes a final-video frame, or calls a second renderer. An older core without actual inline capability fails explicitly; normal read/manual functions remain available. Without live-follow opt-in, reads, hovering, selections and stepping do not render. Timeline/history authorization and preview-cache consent never imply one another.

Only a bounded, exact `current-composite`, `approximate:false`, same-saved-version PNG is accepted. The [kernel frame contract](../docs/reference/timeline-api.md#显式当前帧图像第一切片) defines plugin exclusions and the silent official BGM exception. FPS matching uses bounded exact rational comparison of core source tokens (including `30.0` / `3e1`), maps supported NTSC decimal aliases to N/1001, and accepts exact rational strings; never floating-point coercion or object identity. The client checks canonical base64, byte count, PNG/IHDR dimensions, SHA-256, exact document-raw SHA, reference frame/fps, the core identity certificates and a complete browser decode. Limits are 8 MiB for the entire UTF-8 response including envelope/newline, 8192 px per edge and 16,777,216 pixels; DSH's current image policy can be stricter. No resizing, text truncation or lossy reserialization of `reference.document.raw` / selected raw occurs. The frame reference contains core frame-hit selections, not a locally inferred association: a non-hit selected block is refused unless the user explicitly chooses **position-only**, which does not claim that block appears in the image.

After generation, a **second explicit click** either copies the verified PNG or appends its original `File` plus a reference summary capped at 300 UTF-16 units to the current existing draft through the official sequential conversation API (plugin-owned `InputActions` + `ConversationController` `createDrafts`/`releaseDraftAttachment` facade): capture the collapsed selection start synchronously at click time, recheck the saved reference, then append text and image as separate official calls. Existing text, chips and image attachments are retained; a failed or refused later step compensates only the owned image through an authoritative same-identity readback and reports the partial outcome explicitly. There is no send, upload, paste, destination recapture or automatic retry. Selection/frame/version/Session/cwd/close changes and busy/stale/unknown manual work synchronously invalidate old generated data and cancel pending intake. Actual DSH intake additionally guards revision, composer state, permission, limits, navigation and binding lifetime; a refusal leaves the previous draft unchanged.

Clipboard support/permission refusal is visible and never silently falls back to text. OS clipboard writes cannot be recalled after a later invalidation, and the OS may re-encode PNGs. Temporary decode URLs are revoked; applied draft previews belong to DSH. Certificates identify the render-time inputs with **Fast media stat identity**, not live-atomic media at draft-intake time, a final render, QC or an immutable clipboard byte promise.

### 冷准备、排队与精确定位

另行勾选冷准备后，Host 仅在内核实际广告 `frame.prepare_gfx` 时传 `--prepare-gfx`；可见 HTML 需额外按保存版本确认执行信任。不发送 HTML 正文/任意路径，不新增图层交付 kind；完整当前帧仍经相同原文/版本/FPS/PNG/SHA/浏览器完整解码及草稿二次点击校验。新模式只交付 inline PNG，`path:null`，请求临时件在成功响应前清理；失败账本的恢复限制见[内核合同](../docs/reference/timeline-api.md#显式冷态图形准备完整当前帧)。HTML 仍非沙箱，不能把声明依赖或执行许可描述为零网络/任意代码隔离。

Host 全局 FIFO 最多 1 个执行 + 4 个等待的不同 grant；同 grant 仍须先取消当前请求，面板忙时不暗中积累点击。等待计入原 30 秒 lease，不续租或自动重试。队列条目在获准时取得 nonce/owner/expiry/config 监控；轮到时仍需实际子进程清空。取消只移除自己的条目并等待回收，失败清理不释放残留的拥有权；grant/cwd/配置/卸载使等待与运行请求同样失效。界面只显示诚实的等待/准备/合成状态，不把有限 JSON 伪装成逐阶段图片流。

时间码按已保存 FPS 与规范全局整数帧双向换算，分钟可超过 59；NTSC 为名义 non-drop，不用墙钟秒反推标签。时间码非法原文保留供纠错并暂停引用/播放，不暗用上一合法帧。高级「秒 + 零基帧偏移」仅限整数 FPS，30fps 下 `10 + 5` 为全局帧 305；非整数或未知 FPS 禁用该高级换算。换算本身不查询或授予渲染许可；只有已另行启用的实时跟随才响应播放头变化生成画面。完整合成始终使用规范整数帧，不能把单页图层帧替代 current-composite。

[首次组合记录](../docs/reports/assets/html-preview/closeout-capture.json) 保留当时 QC 阻塞的未完成身份；[授权修正后的验收](../docs/reports/assets/html-preview/qc-correction-capture.json) 另绑定最终包、真实异常、官方宿主及正式链，不覆盖旧证据或把 skip/UNRUN 写成通过。CDP 取消先 shutdown 唤醒 I/O，再等待实际 worker 结束并关闭 fd；自愈跨 worker 关闭同样保留在途 I/O 的 fd，不能仅凭浏览器退出推断线程已回收。

### Manual editing (writes require explicit authorization)

Local Linux and macOS hosts use the same explicit write-token flow. macOS additionally requires the installed core to advertise `platform_support.darwin:true`; an older POSIX core without the macOS path-identity/locking implementation remains read-only. Native arm64 frame preview has a narrower verified FFmpeg/CoreText toolchain boundary, not arbitrary macOS binary support; the authoritative platform restrictions are in [timeline API](../docs/reference/timeline-api.md#显式当前帧图像第一切片). No production profile is upgraded implicitly.

**Warning: confirmed commits, adopt, undo, status and recover can write the selected project and its persistent core history.** Opening/reading is not write permission. Click the explicit Session/project write button; a separate in-memory server token is required and is revoked on close, cwd/session change, expiry or unload. An old core without advertised bounded `--request-stdin` transport stays read-only; read/copy/no-draft fallback does not depend on write support. Legacy timelines are never silently adopted: the adopt acknowledgement names stable-ID and history changes, and incompatible legacy input is refused without rewriting it.

Direct edits share the same explicit grant; there is no review queue. **分割** / S saves a split strictly inside one selected non-gfx clip at the canonical playhead; **移除** / Delete / Backspace saves removal of the selected clips only after explicit confirmation. Shortcuts are scoped to the monitor and timeline, not text entry or native video controls. Gestures reuse the same-version saved clip view: pointer motion only updates local feedback; release submits a move or inward trim for validation. Illegal placements leave the clip at its saved position. Alt temporarily bypasses snapping; snapping does not change the project clock. Closing an internal gap shifts only later clips on that track, rejects crossings, and does not resize the project.

The installed core validates and CAS-publishes the edit. With advertised [`edit-view`](../docs/reference/timeline-api.md#单事务编辑并返回已保存视图), one transaction returns inspect and full query from the committed bytes. Before advancing the grant, Host checks the active fence, the non-replayed receipt against the request and both view versions against its revision; the snapshot head must match the operation ID. With explicit preload support, one globally bounded idle child may wait on an empty pipe. Only a fenced save request can deliver bytes and close its input once; uncertain dispatch never falls back to another child. Cancellation and teardown require actual managed-range quiescence.

Older semantic cores use plan → single-use commit → separate inspect and full query. Both reads must match the committed revision in the receipt, not merely each other. Selection/frame changes before commit invalidate the plan; after dispatch they cannot replace the transaction or its receipt. Both paths retain valid stable selections and never auto-rebase, overwrite or retry an operation.

Regression entry points: [shortcuts and confirmation](tests/client-hardening.test.mjs), [gesture ownership](tests/gesture-epoch.test.mjs), [snapping and gap scope](tests/direct-edit.test.mjs), [edit-view receipt/fence](tests/host-hardening.test.mjs) and [legacy refresh version matching](tests/workbench.test.mjs).

Topbar history provides explicit legacy adoption, current-head undo, status and recovery. Unknown writes report the original operation ID when available and block new edits until settled core status/recover and authoritative readback. A confirmed write whose refresh fails is reported as saved with a stale view, not recategorized as unknown. Undo is a real core transaction, not a browser inverse cache; redo is unsupported. The kernel remains responsible for validation and history.

### Read-only agent integration

The plugin registers `framivra_timeline_read` (inspect/query/source-exact reference), limited to the invoking agent's actual Session workspace. It does not accept Session/cwd overrides, write grants, or edit requests. Full CLI semantic operations are unaffected. Complex changes can be described through conversation; refresh the saved timeline to review the result. No sidebar model-proposal, receipt poll or write proxy is registered. Project content is untrusted data, not instructions.

Text-only and PNG draft appends share a summary capped at 300 UTF-16 code units (including both surrounding newlines) for the exact workspace-relative timeline/version, identity or scoped address, and interval/frame, with optional bounded labels; this cap does not affect preview or clipboard copies. Lossless raw and diagnostic copies remain distinct explicit clipboard actions. No raw timeline/numeric-token/certificate JSON is appended to the composer. A precise locator that cannot fit is refused instead of silently changing its identity.

## Safety boundary

Control requests and responses are bounded at **8 MiB + 64 KiB**, before UTF-8/JSON decoding; diagnostics requests at 16 KiB. Stream byte-brand checks work across loader realms. Child cleanup and completed-frame ownership release are scoped to the exact pre-minted grant owner: cancellation cannot reap another Session's read, and an unrelated read overlapping a successful render cannot leave every Session permanently frame-busy. Failed cleanup remains retryable. Optional output directories are skipped without treating them as media, while containment failures still refuse. An in-flight open has an independent 45-second watchdog (Host deadline: 30 seconds), allowing a late minted grant to be explicitly closed after UI cancellation; query/edit activity remains UI-abortable. If transport dies after minting, bounded grant capacity/expiry is the fallback, not a promise of immediate release.

### Host configuration page (administrator-owned, GUI)

The plugin's connection fields are served by the Host settings service as a **volatile** namespace (`framivra-readonly`) and appear as a real GUI form on the DSH **Plugins → Framivra** bundle page (slot `plugins.bundle.config`, keyed by package name `framivra-dsh-sidebar`). Values persist in the profile's user layer and apply live without remounting the plugin.

- `vtxExecutable`: the literal `vtx` (resolved through `trustedPath`) or a Host-absolute path. Relative paths are rejected by schema, Host, and the page's own local validation.
- `trustedPath`: colon-separated Host-absolute directories (default `/usr/local/bin:/usr/bin:/bin`); empty or relative segments are rejected.
- `vtxConfigFile`: independent absolute `.json` path, or empty to retain the kernel default. Every kernel spawn explicitly sets/clears `VTX_CONFIG`; configured files must be regular, outside Session workspaces and installation directories, and have no symlink ancestors.
- `logMaxPerMinute`: diagnostic log cap (`0…1000`, default `120`); the page includes this advanced field, and changes do not invalidate preview grants.

The page is explicitly an administrator control: preview requests and model tools never modify these values; only the Host administrator sets them on this page, and no grant or write token survives a change. Saving is one atomic mutation pinned to the revision captured when editing started (a later Host-side change can reject the draft, never be silently overwritten by it); a Host rejection keeps the draft, shows the latest Host values, and rebasing onto them is a separate explicit click that never submits by itself. Empty executable/PATH fields submit the documented defaults; an empty config-file field explicitly selects the kernel default. **Changing executable, PATH or config-file selection immediately invalidates every open preview grant, media route and semantic-write authorization with `CONFIG_CHANGED` (409)** — including in-flight renders, which abort and reap. Cleanup-only operations (`close`, frame `cancel`, write revoke/plan invalidation/cancel) still succeed after a change so stale grants can always be torn down. A new open binds the executable and fingerprint of one consistent configuration snapshot; an invalid live configuration surfaces as `CONFIG_INVALID` and grants stay closed rather than falling back to defaults.

**检查保存的配置** verifies the current saved configuration without a Session or timeline: trusted executable resolution, regular-file/trust checks, actual `read/v1` capabilities and advisory `store/v1` capabilities. Read, complete-frame and transaction capabilities are reported separately: the Host filters frame and write claims by its own platform as well as the installed core’s protocol. On Windows, a static frame declaration or playable final MP4 does not qualify the Host for composition or semantic writes. The check never saves a draft, opens a timeline, grants writes or accepts executable/PATH fields from the browser. Save edited fields first. Results are revision-bound; a configuration change hides an old verdict and requires a new check. Missing executable, unsupported protocol, cancellation and network errors show actionable messages rather than a successful syntax-only check.

CLI/profile patching of the user layer remains a debug substitute only and is not a GUI configuration claim.

### 内核管理与配置文档

仅 owner Connection Fetch 的 `/api/framivra/kernel-management` 提供管理操作，不注册模型工具。界面分为内核、配置文件、检查；页面挂载不自动扫描、读配置、安装或探测程序。

- **发现**：先验证[统一受管源码安装登记](<../docs/guides/installation.md#受管非-ai-制作环境>)：固定默认根中的 `installation.json`（64 KiB、ready/non-ai/cdp、固定源码/venv/配置布局及完整提交）；不跟随 symlink、不接受工作区路径，不执行登记内容。随后只读扫描当前连接、受信 PATH、用户 bin、pipx/uv/常用 venv 与插件独立安装根；不执行候选、不递归全盘。最多检查 180 个候选、每个根处理前 24 个子目录；公共 `listDir` 仍一次返回该根完整目录列表。结果仅填入草稿，用户保存后才选用。不支持源码目录自动改造为可执行入口。
- **受管预览登记（当前仅消费端）**：Linux `installation.json` 可选 `previewSupplier` 恰含 `schema: framivra.preview-supplier/v1`、`abi: framivra.preview-window.fixed-wheel/v1` 和 `launcherSha256` / `wheelSha256` / `runtimeProjectionSha256`（各 64 位小写十六进制，不带前缀）。实际路径只从默认安装根派生：`preview/vtx-preview` 以及同目录 `kernel.sha256`（单行、末尾换行）、`kernel.whl`、`runtime/`。扫描对照侧栏独立发布批准清单核对 commit 与三摘要，复查固定路径、workspace 边界、启动器（64 KiB）与 pin 字节，不读取 wheel 正文或执行候选。生产清单目前为空；测试授权不进入发布。安装登记和 owner 保存都不是自签授信。既有 Save 按 revision 记住选择的身份，不改手工独立启动器配置；无登记仍按原流程。现场调用前重新验证登记和字节，并须由实际固定启动器返回匹配的 wheel/投影摘要；它负责 wheel 完整性、目录所有权/权限及投影核对。原生公开 fs/subprocess 的路径验证与启动并非原子操作，不能承诺抵御正在并发写受信安装根的同用户进程。确证失配使旧受管窗口/缓存授权失效并回收活动进程；未知 I/O 不承认媒体有效、不伪造已撤销或已收尾。原有渲染同意、限额、项目和素材判断仍照常生效，不声明支持脚本图形。
- **受管专用启动限定**：Host 从独立批准且已选择的登记获取预期摘要，把唯一首参数 `--managed-preview-pins-v1=<wheelSha256>:<runtimeProjectionSha256>` 附到每次受管探针和窗口调用。启动器在任何 wheel 导入前核对本地 pin、实际 wheel、推导投影摘要及投影目录；拒绝重复、错位、未知版本、错误摘要和受管 `--stage-from`。只有匹配的受管 `--verify` 与合格 `capabilities` 输出 `managed_identity: framivra.preview-window.managed-pins/v1`；Host 不接受缺少该标记的受管能力回执。旧 ABI 和非受管手工调用不加参数或标记。未来入生产清单的启动器必须经独立发布批准并通过该限定；本变更不登记运行时或授予渲染。
- **安装（写操作）**：POSIX 本地可信 `framivra` wheel，最大 64 MiB；计划展示 SHA-256、固定系统 Python 与唯一新目录。一次性短时 nonce 绑定哈希，确认重新核对字节，并将匹配快照交给固定 Python helper。在用户 `~/.local/share/framivra-dsh/kernels/` 下创建独立 venv，离线 pip `--no-index --no-deps`；不 sudo、不升级或覆盖原内核、不自动切换连接。Host 权威默认沙箱必须明确为 `danger-full-access`，受限/未知策略拒绝安装，不申请提权。日志与任务数有上限，任务最多五分钟；取消/卸载回收受管进程，失败目录保留供检查，不承诺自动回滚。没有官方 wheel 下载入口；同版本文件名不能代替哈希或来源信任。该高级 wheel 安装不支持 Windows，也不安装系统依赖/模型；Windows 可使用外部一键安装后扫描、保存、诊断的路径。
- **完整配置**：从已保存 `vtxConfigFile` 读取 UTF-8 原文；缺失文件以空对象草稿开始，只有显式保存才创建。常用字段表单与完整 JSON 并存，未知字段和数字 token 保留；表单修改会重新排版。未设置、null、false、空字符串不混淆，不自动复制模板默认值。已知字段说明区分运行时、组件清单标记和模板声明；某些 `enabled` 并非执行链统一开关。
- **检查边界**：1 MiB / 64 层 / 20,000 节点 / 200 条诊断硬限界；超限失败，不把截断结果当通过。JSON 与已知消费键结构检查不执行外部组件、不读凭证、不连服务，不证明依赖、GPU、模型许可或渲染可用。密钥库、环境变量、timeline 和组件 registry 不作为普通配置文件改写；未知字段虽保留，仍不应在配置中存秘密。
- **保存（写操作）**：预览前后文本并确认；读取回执绑定规范路径、配置身份、内容 hash 和短时 opaque selection token。保存先检查目标未变，再创建不覆盖的同目录备份，并用公共 fs 原子版本 CAS 发布。冲突保留草稿；未知结果禁止直接重试，需读取最新文件比较。GUI 保存同一路径也推进内存 epoch，使旧预览/写授权失效；宿主卸载等待正在进行的文件操作 settle。外部编辑同一文件没有 watcher，必须重新打开工程与授权；不宣称跨进程/并发恶意文件替换的原子执行保证。

受管安装推荐独立配置位置为统一根的 `config.json`（位于 source/venv 外）；文件路径由宿主管理员保存，不由 API 请求传入。VTX 的实际配置选择是 `VTX_CONFIG` 或内核默认文件二选一，不是叠加合并，也不存在可由插件权威推导的完整“有效默认配置”。

### Host/client handshake and sanitized diagnostics

Every shipped build advertises its protocol identity: the grant-free control op `hello` returns `{schema: 'framivra.handshake/v1', host: {plugin, protocol, ops, build}}`, and a successful `open` echoes the same `host` object. Because the Host's grant gate runs before `BAD_OPERATION`, a NEWER client talking to an OLDER running host (e.g. the plugin ZIP was updated but the host process was not restarted) sees `BAD_GRANT` for ops the old host never knew. The client treats `BAD_GRANT` on the grant-free `browse` as a capability mismatch, verifies once via `hello`, and shows an explicit `HOST_TOO_OLD` notice ("refresh the page; if it persists, restart the DSH host") instead of a misleading authorization failure. Old clients keep working unchanged on a new host. After every successful open, the file browser recalibrates: a previously failed listing retries at its current folder (real errors resurface), while a healthy listing issues no new IO.

### Terminal grant expiry is a UI state, not a retry loop

Host grants carry a fixed absolute TTL the Host enforces fail-closed on its own clock regardless of the client. The client therefore treats `BAD_GRANT`/`CONFIG_CHANGED`/`PATH_CHANGED` answers (and the `expires_in_ms` deadline answered by `open`) as **terminal for that grant id**: one actionable banner states that the shown view is a stale read-only snapshot and names the way out (explicit 刷新保存版本 / reopen), and frame generation, references, drafts, and manual writes are all unmounted or disabled — nothing renders, sends, commits or renews automatically. Only a NEW grant (explicit refresh or reopen — a same-id refresh never extends the anchored deadline) or a session change clears the state; the deadline map keys per grant id, and death reports are ignored unless they name the grant currently held, so races between a dying old grant and a freshly minted one cannot lock the live view.  Covered by `tests/grant-expiry.test.mjs`.

The `build` field is a deterministic content fingerprint, not a hand-maintained version: `src:<16hex>` hashes the exact host+client source module list in source runs; `pkg:<16hex>` hashes the shipped lib files plus the client bundle in packaged ZIPs, baked identically into the packaged host and the client bundle (`scripts/package.mjs` self-asserts the two agree). The host freezes its stamp at module load and never re-reads the disk, so it always reports the code actually running. A client that carries a stamp (any built bundle) compares it with the open response's `host.build`: on a real mismatch the open fails closed — the minted grant is released with one best-effort `close` (awaited, never automatically retried; if the close cannot be confirmed reclaimed, the banner says so explicitly instead of implying the session is fully released), no query/edit/frame starts, and the user sees `HOST_BUILD_MISMATCH` with refresh/restart guidance; the `hello` probe after `BAD_GRANT` reports the same verdict. A stamped client that receives **no** host build identity (a running host new enough to answer `open`/`hello` but too old to report `build`) is blocked the same way as `HOST_BUILD_UNVERIFIED` — such a host's feature set is unknowable to this client, so it fails closed instead of guessing. Unstamped clients (source runs, old builds) never block, and equally-stamped builds never compare further.

The Host also emits one sanitized, rate-capped line (`[framivra-dsh-sidebar] control op=… code=… status=… ms=…`) for every non-cancelled failure — including ordinary business rejections — containing no bodies, paths, session ids, grants or media identity. The cap comes from the validated configuration field `logMaxPerMinute` (schema-typed `0…1000`, default `120`; re-validated by the host so no construction path bypasses the bound; changing it never invalidates open previews), and the sink is injectable for tests via Host configuration (`logger`). The cap is volatile: it is re-read for every logged line (plain values and live configuration cells alike), so live changes take effect without a host restart while the current minute's counting continues — a cap change never resets rate limiting, and an invalid or failing read skips the line silently rather than masking the original business failure. `logMaxPerMinute: 0` silences completely: no failure lines, no cap notice, no rollover summary.

- Connection Fetch registers exact `/api/framivra/control` (POST, including workspace browse), `/api/framivra/diagnostics` (POST, saved configuration only), `/api/framivra/kernel-management` (POST, owner-only installation/configuration), `/api/framivra/media` (GET/HEAD) and `/api/framivra/frame` (POST, **streaming owner carrier**) routes. Streaming here preserves request cancellation; the frame still has a finite, bounded JSON body/response (16 KiB request, 8 MiB UTF-8 response). The DSH carrier's owner-Peer admission is the authentication boundary; there is no raw WebServer route or standalone service. Owner/anonymous HTTP behavior must be checked on the intended carrier; route-registration tests alone are not authentication evidence.
- Host chooses Session cwd. Browser gets a 30-minute opaque grant (maximum 32 active) bound to the live Session object and cwd; the media route accepts only Session/grant/opaque-mediaID, never a path. Grants are process-local and disappear on unload.
- `ctx.fs.resolve/contains/stat` enforce canonical containment and regular files. Symlink escape, URL, NUL, traversal, absolute input and cross-session grants are rejected. Local shared-path mapping only; no `node:fs` permission bypass. Every media pull revalidates the grant and output identity/version. A filesystem cannot offer atomic “resolve + run child/open file” through these contracts: concurrent hostile filesystem replacement remains a host-level TOCTOU limitation, not a sandbox guarantee.
- Configure `vtxExecutable` as an administrator-trusted absolute path when outside system PATH. Default `vtx` resolution uses only `/usr/local/bin:/usr/bin:/bin`; custom `trustedPath` entries must all be absolute. Executables resolving inside the Session workspace are rejected. Child argv never uses a shell, cwd is the executable directory (not project cwd), read stdin is ignored; semantic requests use only public batch `stdio.stdin.data` with official `store [plan] --request-stdin` (8 MiB UTF-8 limit, never `/dev/stdin` reopening or temporary request files); safe Python environment clears `PYTHONPATH/PYTHONHOME` and sets `PYTHONDONTWRITEBYTECODE=1` / `PYTHONSAFEPATH=1`. The selected executable/parent directory must itself be trusted; a Python launcher is not accepted instead of installed `vtx`.
- Reads have a 30-second deadline, abort with request cancellation and plugin unload, and cap stdout to 8 MiB. `collected.stdout.readFrom(0).lossy` rejects truncated JSON. Every read, including successful commands, terminates its managed range and awaits **both** direct-result settlement and public `waitForExit()` quiescence before releasing ownership. Cleanup has an independent 5-second bound; an unobservable/stuck range produces `PROCESS_CLEANUP_FAILED`, retains ownership for unload retry, and unload reports failure rather than silently dropping the range. Real 30-second Host deadline testing returned only after cleanup (about 31 seconds). Provider containment limits still apply, including weaker fallback providers' inability to guarantee escaped descendants.
- Complete JSON uses the same native `JSON.parse` source-context codec on Host and Client, preserving numeric tokens with native `JSON.rawJSON` through HTTP, details and serialization. No handwritten JSON parser, network dependency, decimal/BigInt string substitution or second timeline parser is used. Native support is actually probed on each decode; missing support explicitly refuses instead of displaying rounded fields. Frame/index selectors and returned query indices/ranges must remain canonical nonnegative safe integers; vtx-emitted document/extension numeric tokens remain uninterpreted and wire-lossless. This is **not original-source numeric or lexical fidelity**: the current Python upstream already converts decimal/exponent source tokens to float before emitting read/v1 (e.g. source `1.0000000000000001` may emit `1.0`). The sidebar cannot recover that precision. Any “all fields” claim means the vtx-emitted read document only; `content_version` hashes source bytes but does not make the emitted document source-exact. The separate `reference/v1` action now supplies source-exact `document.raw` and selected `raw` strings; it does not change read/v1 preview fields or claim render fidelity. If an installed read/v1 cannot inspect a timeline (for example an unsupported numeric form), preview/open still fails explicitly rather than falling back to another parser. Exit 1/2, schema mismatch and diagnostics are surfaced separately.
- Media is pull-streamed in at most 64 KiB windows using `ctx.fs.readByteRange`. Supports GET, HEAD, one bounded/open/suffix byte Range, 206/416, Content-Length and cancellation. Multiple/malformed ranges fail closed. It does not reuse `/api/file`, buffer whole MP4s, or accept arbitrary filesystem paths.
