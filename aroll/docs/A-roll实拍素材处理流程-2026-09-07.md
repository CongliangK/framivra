# A-roll 实拍素材处理全流程（2026-09-07 首跑实录，可复用）

> 首次真实素材生产链：Audacity 多轨口播录音 + 相机 4K 出镜视频 → 9 条「头部统一、口型同步、降噪、去真空」的成品素材。
> 本文档是可照抄的流程手册；数据与溯源见 `voice-ime/cache/av_sync/manifest.json` 与各步骤产物。
> 关联决策：D23（实拍规范）/ D25（降噪链）/ D26（双系统同步）。

## 0. 输入与产出

- 输入：`口播.aup3`（Audacity 3.7 工程，mono 44.1kHz float32，每段口播一条轨）+ SD 卡 `P104xxxx.MP4`（4K 29.97fps，相机内录麦为同步参考轨）
- 产出：`voice-ime/assets/aroll/视频一~九.mp4`（4K、NVENC 150Mbps、音轨=麦克风降噪版、头部统一构图）

## 1. aup3 解析与提取（`cache/aup3_extract/aup3_extract.py`）

- `.aup3` = SQLite。表：`project(dict,doc)` / `autosave` / `sampleblocks(blockid, samples...)`。
- 二进制格式（对照官方 `au3/libraries/au3-project-file-io/ProjectSerializer.cpp`）：dict = `FT_Name(0x0f)+u16 id+u16字节数+UTF-32LE`；doc = token 流（1=开始 2=结束 3=字符串 4=整型 12=原始文本，小端定宽）；采样 = float32LE 裸 PCM。
- 轨道树：`wavetrack → waveclip(offset) → sequence → waveblock(start, blockid)`；blockid 指向 sampleblocks 表。
- **删除的片段不会从库里清掉**（孤儿块可恢复 = 废片找回；也意味着工程越删越大）。
- Audacity 开着工程时须复制 `aup3+wal+shm` 三件套到缓存目录再操作。
- 掐头去尾（`trim_takes.py`）：300-3400Hz 帧级 RMS、-48dBFS 阈值、头 150ms/尾 250ms 气口；中部气口保留（后续按静音谷切分要用）。

## 2. ASR 配对与废片判定（复用 voice-ime 产品 sidecar）

- Qwen3-ASR sidecar：`POST http://127.0.0.1:18081/transcribe {"audio": 本地wav路径, "language": "Chinese"}`（注意 language 用全称；空闲 5s 自动卸载模型，先 `POST /warm`；输入法服务本身可直接占用）。
- 12 视频 × 9 take 全转写 → 文本匹配配对；**废片判定 = 视频文本是某 take 的前缀且比例低**（12%~70% 中断点）。
- 16k mono wav 输入即可；转写很快（4K 视频直接抽轨）。

## 3. 双系统同步（`sync_audio.py`，D26 工具）

- 8 对直接跑（相机 MP4 × take WAV → conform WAV）；短素材（<50s）加 `--win 10 --hop 5`。
- 残差分级：0.6~1.3ms 优；3.8~4.5ms 可接受（<10ms 口播感知阈值）。
- **P1040019 教训**：全局拟合报 -19000ppm「漂移」≠ 时钟漂移，= 有一段对不上。逐窗全范围搜索定位：前 56.3s offset 恒定完美匹配（同一遍），take 尾部多录 6.5s 零碎废音（-10dB 短句，无口型对应）。**下「两遍录音/口型对不上」结论前必须做内容级验证**（ASR 段落对比 + 静音结构对比）——本次初判即被用户听感推翻。

## 4. 音轨替换重封装

- `ffmpeg -nostdin -y -i 视频 -i 同步.wav -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 320k -movflags +faststart`
- **`-nostdin` 必加**：在 `while read` 循环里 ffmpeg 会偷吃 stdin 的后续行（本次实际踩坑）。
- zsh 注意：`set -- $var` 不分词，用 `printf '%s\n' ... | while read a b`。

## 5. 口型感知全局偏移（用户主观验收驱动）

- 波形级同步（亚毫秒）≠ 观感对齐：唇部预备动作天然领先声音，用户验收要求**全部音轨后移 200ms**（前置静音实现）。
- 后续视频可沿用 200ms 为默认值，仍以用户验收为准（素材级已验证的现值写进 manifest）。

## 6. 降噪（D25 标准链，`~/.agents/skills/video/scripts/denoise_voice.py`）

- 陷波(80Hz HP+50/100/150Hz notch) → Resemble 仅降噪级 → 48kHz；单文件 `denoise_voice.py <in> <out>`，CPU 批量 ~621s 音频几分钟。
- 实测：50Hz 消 ~40dB、100Hz ~20dB、150Hz ~14dB；零时长漂移零滞后；语音 RMS -0.3~-1.7dB。
- **处理对象用无损 PCM 源**（synced wav），不要解成品 AAC 再编（避免二代有损）。

## 7. 头尾真空切割（本次最大的坑）

- 正解：**对已对齐的全长成品做单输入 copy 切割**：`ffmpeg -ss K -to T -i aligned.mp4 -c copy out.mp4`（LosslessCut 路径，A/V 由 ffmpeg 一致 seek，实测错位 0.0ms，音视频都零代损）。
- 切点：语音边界（带通 RMS -50dBFS，降噪后底噪 -60dB 余量足）+ 头 150ms/尾 300ms pad → 吸附关键帧（相机 GOP=0.5s，关键帧时刻用 ffprobe packet flags=K 提取）。
- **错误路径（勿走）**：双输入 `-ss` 切视频 copy + 重切音频重封 → A/V 错位 27~58ms 且方向不稳定（mp4/mkv 都一样，ffmpeg 时间戳处理不可靠）；测量驱动补偿也无效（负补偿被 muxer 对齐决策吃掉）。
- QC 教训 ×3：
  - 「相关系数 1.000」可能是静音稀释假象（前置真空段占多数时）；
  - 对短段单独 FFT 带通产生边界 Gibbs 振铃伪峰；
  - A/V 对齐的仲裁要用两种独立方法：**视频首帧哈希匹配源关键帧** + **成熟 GCC-PHAT 测音轨平移**（自写 GCC 先用已知对齐样本校准方向）。

## 8. 头部位置统一 + 放大（构图对齐）

- Haar 人脸检测（OpenCV `haarcascade_frontalface_default.xml`，4K 帧缩到 960 宽检测更稳，45/45 命中）：每条 5 帧取脸中心中位数。
- 每条独立 crop：放大 20% = `crop=3200:1800:tx:ty` → `scale=3840:2160:flags=lanczos`；tx/ty 由「脸中心→统一目标点」反解 + clamp（y 平移余量仅 ±180px@20%，目标点选 0.435 = 余量内全员可达的最靠上位置）。
- 公式方向：脸要靠上 → **窗口中心在脸下方**（`cy = fy + (0.5-TY)*CH`，写反会得到 0.565）。
- 编码：`h264_nvenc -preset p6 -tune hq -rc vbr -b:v 150M`（视觉近无损），音轨 copy。
- 按约束不做视频内稳定（残余 2~3% 浮动=身体自然晃动）；可选升级=逐条微调放大率使**头部大小**也统一（本次未做，脸宽差 15%）。
