## 一、文件结构（破译结论）

`.aup3` = SQLite 数据库，4 张表：

| 表 | 内容 |
|---|---|
| `project` | `dict`（字符串字典）+ `doc`（二进制序列化的工程 XML 树） |
| `autosave` | 空（工程已完整保存） |
| `sampleblocks` | 9 个音频块：float32LE 裸 PCM + min/max/rms 摘要（用于校验解码正确性，9/9 完美吻合） |

二进制格式与 Audacity 官方 `au3/libraries/au3-project-file-io/ProjectSerializer.cpp` 对照破译：
字典记录 = `FT_Name(0x0f) + u16 id + u16字节长 + UTF-32LE`；doc = token 流（`1=开始标签 2=结束标签 3=字符串 4=整型 9=浮点 12=原始文本`，字段一律小端定宽）。轨道→clip→sequence→`waveblock` 节点携带 `blockid` 指向 sampleblocks 表。

1. **50Hz 工频哼声显著**（占总能量 -0.9~-12dB，100Hz 二次谐波同在）——与 D25 诊断的 Pin1 问题签名一致。这些素材进成片前必须过 D25 降噪链（陷波 notch → Resemble）。
2. **采样率 44100Hz**——正式管线是 48kHz 基准（D24/D25），用前需重采样。
3. **单文件多轨方案完全可行**：aup3 可被纯命令行解析提取（本目录 `aup3_extract.py` 可复用，零第三方依赖），不需要打开 Audacity 手工导出。适合「一条时间线管理多 take」的录制习惯；孤儿块还附带废片找回能力。

## 裁剪方法与安全验证（`trim_takes.py`）

- 检测：300-3400Hz 带通（滤除 50/100/150Hz 工频哼声——直接用宽带阈值会被哼声垫底导致测不到静音）后 1024/512 帧分帧 RMS，-48dBFS 帧级阈值；实测带通后底噪 -62~-79dBFS，余量充足。
- 裁剪：首/末活动帧外扩头 150ms / 尾 250ms 气口；中部段间气口**保留**（repack_voice.py 后续按静音谷切分依赖它们）。
- 边界审计：9 条 take 被裁段帧级 RMS 最大 0.0034（阈值 0.004 的 85% 以下），尖峰均为孤立瞬态杂音（停录咔哒/桌碰），**未切到任何语音**。教训：对短段单独做 FFT 带通会产生边界 Gibbs 振铃伪影，审计必须与检测同口径（整段滤波后切片）。
