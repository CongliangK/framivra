## 逐项核查结论

### 1. 代码精读

**seg_encoder_kind 单一来源：属实。** grep 全仓，seg 键的编码器 token 只有两个产生点：`composite.prepare_layers`（实际编码）与各键重算点全部 import 同一 `encoders.seg_encoder_kind`（hygiene.py:186、subs.py:238、timeline_diff.py:131）。无第二实现。`seg_key()` 签名改为必传 encoder 后，grep `seg_key(` 的全部调用点（composite 382 / hygiene 197 / subs 254 / timeline_diff 130 及其包装、tests）均已适配，无遗漏调用方（tests/test_timeline_diff.py 走 `_clip_seg_key` 包装，同步生效）。

**gc 键集漂移（重点裁定）：分叉可能存在，后果是效率损失，不是正确性损失。定级 P2。**
- 静态推演：`gc_plan → _current_keys` 与 `prepare_layers` 各自独立调用 `seg_encoder_kind(c)`，即各自独立跑一次 `nvenc_ok` 探测。两者判据同源但**判据含运行时探测结果**——「VTX_SEG_NVENC 未设」场景两者必同值；「NVENC 硬件故障回落 x264」场景若探测结果在渲染时刻与 gc 时刻之间翻转（瞬时故障恢复，或跨进程两次调用之间硬件状态变化），键集即分叉。
- 分叉后果链（已核 gc_plan 实现，hygiene.py:218-223）：gc 按 `x.stem not in live_keys` 判垃圾并物理删除。渲染落盘 x264 键、gc 按 nvenc 键算集 → 现存 seg 全部判垃圾被删 → **下一轮全量重编码**。反向分叉（gc 判 x264 集、盘上是 nvenc 键）同样误删。
- **为何不是正确性损失**：所有消费方（subs._layer_ready、render 的图层检查、prepare 的缓存命中）都按「当下计算出的精确键」找文件，天然不可能命中错误编码器的陈旧 seg——内容寻址设计下误删的代价上限就是重编码。结论：**效率损失，非正确性损失**。
- 设计层面的病根：缓存键掺入了运行时探测值（硬件状态），违反「键只应由输入内容+配置决定」的原则。若把 seg 键的编码器 token 改为只看 env（探测失败仅影响实际编码器选择不影响键），或对 nvenc_ok 做进程级 memo，漂移窗口即消除。建议阶段4 处理。
- 附带发现（并入本条）：`gc --dry` 走 dry Ctx → `nvenc_ok` 恒 True → 恒算 nvenc 键。在探测失败回落 x264 的机器上，`gc --dry` 会把活 seg 误报为垃圾，而真实 `vtx gc`（非 dry，真探测）反而不会删——dry 预览与真实回收口径可分叉。同属 P2 的一部分。

**subs/timeline_diff 越白名单波及（重点裁定）：必要，改动干净，无夹带。**
- subs.py：`_layer_ready` 是按精确键做 `seg.exists()` 只读检查——不补 encoder token，NVENC 化后它永远找旧 x264 键的文件，恒 miss，subs preview 会误报图层素材缺失。**不改必坏，波及成立**。
- timeline_diff.py：`_clip_seg_key` 的输出进入 diff 报告的 old_key/new_key 与段图层恒等判定。diff 两侧用同一 DiffCtx 口径，不补 token 也能自洽比较（token 不随 clip 变化不影响「改 clip → 键变」），但报告出的键会与真实缓存键不符，属口径失真而非功能损坏——波及**合理但必要性弱于 subs**。
- 夹带检查：subs.py 改动 = import + 判定一次 + 传参，零行为变化；timeline_diff.py = import + 传参 + `DiffCtx.dry=True` 类属性。grep 证实 timeline_diff 内无其他 `c.dry` 读取点，`dry=True` 唯一效果是让 `nvenc_ok` 短路不真探测（diff 是纯读命令，不起 ffmpeg 探测子进程是正确语义），对既有用法零影响。真机自 diff PASS 佐证。
- NIT：`_layer_ready` docstring 声称「只读检查，不触发编码/渲染」，现在非 dry 下会跑一次 nvenc 探测 ffmpeg 子进程（几十 ms）且探测失败时打印告警行——轻微副作用违背 docstring 措辞。

**nvenc_budget 信号量：实现正确。**
- 惰性初始化：`_nvenc_sem()` 全程持 `_NVENC_SEM_LOCK` 后判空再建，两线程同时首调安全。
- reset_nvenc_budget：仅测试用、锁内置 None，docstring 明确「改 env 后须重置」——用途与限制如实。
- 异常安全：`@contextlib.contextmanager`，acquire 计数 `got` 在 `finally` 释放；with 体抛异常时生成器在 yield 点被 throw，finally 必执行，槽不泄漏。`run_ffmpeg_task` 的 `with nvenc_budget(c) if nvenc else nullcontext()` 语义正确。
