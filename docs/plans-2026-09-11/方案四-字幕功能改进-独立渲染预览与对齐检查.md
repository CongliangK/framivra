# 方案四：字幕功能改进——独立预览与渲染前对齐检查（功能改进方向 · v2 修订版）

> 目标：让智能体改字幕「秒级看到效果、渲染前发现对齐错误」，消灭 v39 式「渲染完整片才发现字幕漂移 4.3s」的事故循环。
> v2 修订说明：撤销 v1 的「字幕解耦独立烧录 pass」核心设计（红队 F4 证伪，见下），本方案聚焦 `subs check / subs preview` 两个纯收益命令。

## 〇、v1 → v2 的证据修订（红队 F4）

1. **v1「改任何一条字幕 = 强制段重渲 + 全链验证」与代码事实不符**：段键只含**该段窗口内**的 ass 字节（`composite.py:234-252`，`write_seg_ass` 只写落进 [a,b) 的字幕，`composite.py:88-101`），改一条字幕只失效其覆盖的 1-2 个段（~10-25s），并非全链。
2. **解耦设计会拖慢冷跑**：改为「无字幕母带 + mux 前独立烧录 pass」后，每次冷跑多一整遍 16746 帧解码+重编码（估计 +90-150s），与方案三的 4 分钟目标直接冲突；现状段内 `subtitles` 滤镜烧录（`composite.py:200-201`）零额外 pass 成本。
3. 结论：**保留段内烧录为默认**，本方案只做无争议的纯收益部分（subs check / preview / 配方引导）。若未来确需「干净母带」产物，作为可选 `--burn-subtitles off` 开关另行评估，不进本方案验收。

## 一、调查结论（卡点证据，修订后）

1. **无字幕独立预览**：ass 由 `write_global_ass` 生成但只是 video 内部产物，无 `subs` 独立 CLI 阶段；智能体要看字幕效果只能渲染视频。历史上曾专门搭过 Blender 字幕 alpha 层旁路系统（`cache/v37/blender_subs_alpha_v37.log`、`cache/subs_alpha.mov` 1.7GB 遗留），后废弃——证明该需求长期存在且从未被一等满足。
2. **无字幕独立预览**：ass 由 `write_global_ass` 生成但只是 video 内部产物，无 `subs` 独立 CLI 阶段；智能体要看字幕效果只能渲染视频。历史上曾专门搭过 Blender 字幕 alpha 层旁路系统（`cache/v37/blender_subs_alpha_v37.log`、`cache/subs_alpha.mov` 1.7GB 遗留），后废弃——证明该需求长期存在且从未被一等满足。
3. **v39 事故**（`cache/v39/inv1-subs-shift.md`）：字幕超前口播最大 4.3s，v3.3–v3.8 各轮刚体平移均未发现，最终 12 条字幕重开窗、触发一整轮 v3.9 全链修订。这种漂移本质是**字幕窗 vs 口播时间窗的纯文本比对**，完全可以在渲染前发现。
4. 字幕 QC 只有阅读速度 audit，「字幕-口播对齐」无自动检查；QC 报告也无与上一版的 diff。

## 二、推荐实施路线（指引性质，可按实际情况调整）

> 本节是调查时点的推荐路径，不是硬性要求。执行中若发现更好的命令形态或交互方式（例如把 subs check 并入 validate、或 preview 改为批量模式），可自行调整——但第三节的开发要求与第四节的验收门槛不随之放宽，且实际路径与偏离原因须如实写入交付报告。
> **执行纪律（硬性）**：本规划不预设自己完全正确——路径推荐基于调查时点快照，先校准（开工前当次重测基线，与本文记载偏差 >20% 先修正文档前提再动手），再实施；判断标准是你自己的实测，不是文档断言。
> **组织方式（硬性）**：实施智能体作为**总控**对本方案交付质量负总责：尽可能把具体开发工作（写代码、跑实验、跑回归、写测试）派给**子智能体**执行，总控负责任务分解、派发（任务书自包含：目标/涉及文件/已知坑/完成定义/要求回传命令输出等证据）、裁定与验收；每个阶段性成果须由**未参与实现的独立子智能体**做对抗式审查（核原始日志、找验收可钻空子处、查协议与规范破坏），问题修复后复审关闭，审查报告随交付归档，总控不得审查自己派发的成果。
> **代码纪律（硬性，违反即审查不通过）**：风格与周边代码一致（命名/注释密度/`[timing]` 打点惯例），注释只写代码表达不了的约束；改动前读 `docs/DEV.md` 与 `skill/references/`，帧确定性协议、缓存键内容寻址语义、段边界机制不得绕过；行为改动带测试、性能改动带可复现基准脚本；小步提交、不绕过 lint/检查、实验代码收编或删除留结论；基线数字、证伪结论、新默认值写入 `docs/DEV.md` 与 runbook 之前，对应工作不算完成。

### 阶段 1：`vtx subs` 独立阶段（1 天）
1. 新增 `vtx subs render`：独立产出 `cache/subs.ass`（复用 `write_global_ass`），内容寻址缓存。
2. 新增 `vtx subs preview <时间码|帧号>`：取任一已缓存段的对应帧 + ffmpeg `subtitles` 滤镜合成一张静态预览图（秒级），输出路径打印给调用方。支持一次传多个时间点输出多张。
3. 新增 `vtx subs check`：自动检查——①每条字幕窗 vs 对应 voice/口播事件窗的偏移（超阈值标红，正是 v39 漂移检测）；②阅读速度（CPS）；③时间重叠；④行宽/行数超限。输出机器可读 JSON + 人类可读表格。

### 阶段 2：字幕改动的快速确认回路（1 天，替代原解耦设计）
4. 依赖方案五的区间渲染能力提供字幕确认路径：改字幕 → `vtx subs check`（秒级）→ `vtx video --draft --range <该字幕所在窗口>`（≤10s）→ 确认。由于段键只含本段字幕，受影响段重渲代价天然可控（~10-25s），无需解耦。
5. （可选开关，不进验收）`--burn-subtitles off`：产出无字幕母带的能力预留，明确标注「会额外增加一整遍烧录 pass 成本」，供存档场景手动使用。

### 阶段 3：配方与引导（半天）
7. runbook 拆出「R2s 纯字幕修订」配方：`改 make_subs.py → vtx subs check → vtx subs preview 抽查 → vtx mux`，并在 SKILL.md CLI 速查置顶。
8. `vtx qc diff` 顺带支持字幕项与上一版报告对比。

## 三、开发要求

1. `vtx subs check` 必须零渲染完成全部检查（纯文本/JSON 处理），且能在时间线层面运行（不需要任何视频产物存在）。
2. **不改任何缓存键语义与烧录路径**：正式渲染产物（含字幕烧录位置/样式）与现行为像素级一致（回归比对为证），ASS 模板与字体解析路径不变。
3. `subs preview` 单张预览耗时应 ≤5s，必须可在无 gfx/段缓存的全新环境运行（可用 draft 段兜底）。
4. 所有新命令输出对智能体友好：末行打印明确的 PASS/FAIL 与产物路径。

## 四、验收要求（严格、可量化、防自夸）

> 验收场景直接取自历史事故，用「当时会被抓住吗」作为标准。

1. **对齐检查有效性（硬门槛）**：把 `cache/v39/inv1-subs-shift.md` 描述的漂移状态构造成测试 timeline，`vtx subs check` 必须标红（报告偏移 ≥4s 的字幕条目）；用当前正常 timeline 跑必须零误报。两组结果 JSON 均需提交。
2. **迭代提速（硬门槛）**：只改 1 条字幕文本后，从执行命令到拿到该字幕的可视预览图 **≤30s 墙钟**（计时日志为证；基线 ≥2 分钟）。
3. **确认回路**：改 1 条字幕后走「subs check → 区间渲染所在窗口」路径，受影响段重渲 ≤2 段（缓存命中日志为证），正式渲染产物与「直接改 ass 重渲」的对应帧像素一致。
4. **检查覆盖**：`subs check` 对人工构造的 4 类坏样本（超前 2s、滞后 2s、CPS 超限、时间重叠）全部报错，对正常样本全绿。
5. **回归（硬门槛）**：`vtx all` 后 qc_report 与基线一致，`subs preview` 抽查 5 个时间点字幕渲染位置与成片逐像素一致（证明默认烧录路径未被本方案改变）。
6. **诚实条款**：任何检查项实现不了（如口播事件缺时间戳的字幕条）必须输出 WARN 而非静默跳过，并在报告中列出覆盖率（检查了 N 条 / 共 M 条）。
