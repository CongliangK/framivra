## 二、核心裁定的对抗攻击记录（任务书审查重点 1）

**裁定**：免检记录改为「按检查项记忆」——`checks: {检查名: 上轮是否 pass}`，免检仅对「上轮该项 pass 且探测帧全部落在 stat 一致段内」生效；失败轮也刷新记录（失败项记忆 False → 下轮必实测）；同名多项须全部 pass 才可免检（`vtx/qc.py:97-104`）。

**攻击 a）构造「探测帧内容变但段键不变/段 stat 不变」反例**：
- 段键输入集（`vtx/composite.py:243-261`）= 段区间 + 画布/模式/draft/gpu + 每相交层（上游内容键 + clip JSON + x/y/w2/h2）+ 段字幕 ass 字节。视频探测帧内容的全部决定因素（底轨源、上层 gfx/clip、字幕、布局、参数）均入键。
- **纯音频变化**（音轨 volume 改 0.6→1.0）不入段键 → vseg 不重渲（语义正确，视频流未变）→ 但 mux 后 final.mp4 stat 变 → `_load_qc_pass_record` final 绑定失配 → **整记录失效全检**（安全方向）；响度走 loudness_cache 回执，final 变 → 键变 → 重测（§四-9 实测闭环）。**结论：视频探测免检在纯音频变化下安全**。
- timeline 任何改动 → 至少一项键输入变 → 段名变 → list.txt 更新 + mux 后 final stat 变 → 记录失效。**中途无免检窗口**。
- **穿透需同时伪造**：段文件 stat（size+mtime_ns）与 final stat——复合伪造落在方案已声明的免检风险内，三重明示齐备并实测确认（⚠ 终端行 `vtx/qc.py:425-427`、`skipped_probes` 字段入 qc_report.json `:421`、`--strict` 整体禁用 `:206`；§四-7 变体 B 实测）。
- **裁定安全性结论：成立**。证据链「上轮该项 pass + final (size,mtime_ns) 不变 + 覆盖段 stat 不变」与全过门同一内容绑定强度，仅粒度细化；✗ 项永不免检（c4_mini 每轮实测复现 ✗，skipped_probes 抽查确认不在免检集，§四-6）。

**攻击 b）final stat 绑定绕过**：mux 重封装但视频流未变（只换音轨）→ final stat 变 → 全检（安全方向，冗余但无害）；反向复合伪造见上。**「明示」落地核实：真实**（三件套均在，proj3 变体 B 实测输出粘贴 §四-7）。

**攻击 c）免检判定与 checks 输出的项数/名称/顺序恒定**：归档四份日志（全检 r1 / 免检 r2/r3 / strict）checks 名称序列 75 项**逐项完全一致**（本人解析比对，`r1==r2==r3==strict`，diff 空集）；本人 --strict 复跑后再比对 live report 与归档 r1 序列一致（§四-5）。免检项照常占位（`ok_exempt` 走同一 `ok()` 入账顺序）。**无「免检悄悄少检」**。
