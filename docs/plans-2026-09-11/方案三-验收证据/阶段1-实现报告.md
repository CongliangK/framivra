### 2. 响度测量共享（新模块 vtx/loudness_cache.py）
- **新文件 `vtx/loudness_cache.py`**（全文件 97 行）：
  - 回执文件 `<项目>/cache/audio/loudness_receipts.json`，结构
    `{"entries": {key: {"path","size","mtime_ns","digest","i_lufs","tp_dbfs","when"}}}`；
  - 键 = `sha1(f"{path}|{size}|{mtime_ns}|{digest}")[:12]`，digest 用
    `cache_state.media_stat_digest`（首尾 64KB 采样哈希，与 hygiene._fp 同判据）
    ——`_key_of` :36；文件任何变动（size/mtime/内容采样）→ 键变 → 自然失效重测；
  - `lookup(path, root=None)` :59、`measure_and_store(path, run_fn, root=None)` :74
    ——run_fn() -> (i_lufs, tp_dbfs)，模块不依赖 Ctx（scripts 侧复用）；写入原子
    （tmp+os.replace），进程内 `threading.Lock` 防并发读-改-写丢笔（对齐
    hygiene._MANIFEST_LOCK 惯例）；i/tp 为 None 不入回执。
- **消费点 A（qc.py）**：`vtx/qc.py:326-343`——先 `lookup(final, root=c.root)`，
  命中直接用（打「（回执命中，免测）」）；未命中测量（-vn+peak）后归档。
- **消费点 B（content_gates.py G2/G3）**：`scripts/content_gates.py:242`（命中
  查询）+ `:246-278`（命中→G2/G3 直接用回执值，全片 pass 只保留
  `[0:v]blackdetect` 单链；未命中→现行合并命令照旧测 I/TP（G7 照跑），测得后
  `measure_and_store` 归档 :283-286）+ `:288-301`（命中分支的 G2/G3 gate 文案）。
  回落语义不变：合并失败仍回落两步（:275-279）；命中态黑场单链失败回落独立
  blackdetect（:260-262）。
- `scripts/content_gates.py:44-50`：sys.path 注入 repo/vtx（与 tests/test_*.py
  同惯例）+ `import loudness_cache`。
- post_loudness.py 不动（总控裁定：wav 域/解码域语义不同，DEV.md 明言 wav 域

## 二、设计裁定记录（含与方案原文/任务书的偏差）

1. **G10 packets 为校准新增项（方向修正，非偏差）**：方案 v2 原文把 gates 大头
   归因 G1；〇b 当次校准（2026-09-13）改写为 G10 `-count_frames` 26.6s 占 72%，
   G1 仅 ~3.5s。本实现按校准执行：G10 收益实测 **-29.2s**（36.6→7.4s 的主体），
   G1 批量化收益实测 **-2.6s**（逐窗 4.4s → 批量 1.8s，阶段1-g1等价.log）——
   「G1 降级为顺手项」的定位修正被本次实测再次确认。
2. **【重要偏差·留总控复审】免检记录写入门：由「全检全过才写」改为「按检查项
   记忆、每轮刷新」**。任务书原文：*「qc 全检全部通过时写……qc 有任何 ✗ 或
   dry → 不写；已有记录但本轮全检未全过 → 删记录」*。该门与验收要求
   *「第二次三次 ≤6s（温态免检生效）……74/75 不变（c4_mini 为已证伪探针假
   阴性）」*在 bench_p2 上互斥：c4_mini 恒 ✗（见阶段1-qc-r1.log:72）→ 按原文
   记录永不建立 → 免检永不生效 → ≤6s 与「免检生效」不可达。实现前曾以
   AskUserQuestion 问询总控，未获应答，按最佳判断裁定为按检查项记忆：
   - 记录每轮刷新，`"checks": {检查名: 上轮是否 pass}`；免检仅对「上轮该项
     pass **且** 其探测帧全部落在 stat 一致段内」的项生效；**✗ 项永远实测**
     （下轮必复测，持续失败持续可见）→ 74/75 逐轮不变（阶段1-qc-r2.log:72
     c4_mini 每轮实测复现 ✗）；
   - 安全性论证：逐项免检的证据链 =「上轮该检查 pass」+「final (size,mtime_ns)
     不变」+「覆盖段文件 (size,mtime_ns) 不变」——与全过门同一内容绑定强度，
     仅粒度从「整轮」细化为「单项」；免检的已声明风险（段内篡改且保 stat 不变
     则不查）不变；
   - 失败轮也刷新记录的后果：失败项记忆 False → 下轮实测（更严）；同名多项
     检查（如同名 gfx 页两处 clip）须全部 pass 才可免检（防一项假阴性被另一项
     真过掩盖），`_write_qc_pass_record` :97 的合并语义。
   - 若总控复审否决此裁定，回退方式：`_write_qc_pass_record` 改为全过才写+
     失败删档（一处函数改动），但 bench_p2 验收的 ≤6s/免检生效两项将随之不可达，
   需一并改验收口径。
3. **【次级偏差】段枚举以 cache/vseg/list.txt 为准，而非任务书的 glob
   `seg*_{a:06d}_{key}.mp4`**：直接 glob 会把同槽旧键残留（gc 未跑时同一 si
   两个不同 key 的段文件并存）也当成生效段，产生重叠 [a,b) 区间——stat 未变
   的陈旧段可为被篡改的现役段所在帧错误背书（免检判定只认 stat，不读段内容）。
   list.txt 是最近一次段渲染的拼接清单（render_segmented 每轮重写，concat 的
   实际来源），以其为准则免检所绑定的段恰是构成 final 的段。清单缺失/含非标准
   段名/段起点非 0 或非严格递增 → 返回 None → 机制不生效全检（保守回落）。
4. **任务书内部文面冲突的处理（响度「永远实测」vs 回执免测）**：改动5 写
   「全局元数据项（帧数/时长/分辨率/响度/并发窗能量）永远实测」，改动2 写 qc
   响度「命中→直接用并打（回执命中，免测）」。按改动2（专门针对响度的条款）
   实现：响度不受**段免检**机制豁免（不在 skipped_probes 内），但走 loudness_
   cache 回执（内容键绑定，等价于「同一测量结论的复用」而非「未测量」）。
   帧数/时长/分辨率/并发窗能量四项则字面意义上的永远实测（阶段1-qc-r2.log:2-3、76）。
5. 其余按任务书裁定原样实现：回执键/文件布局/run_fn 解耦/threading.Lock/原子写；
   G1 批 ≤16 窗、回落语义、[timing] 打点格式；G10 --count-frames 开关与 detail
   口径注明；post_loudness 不动；dry-run 整阶段跳过（既有行为）。
