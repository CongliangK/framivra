## 三、本方案手段落地明细

1. **qc 响度 -vn**（vtx/qc.py:162 一行）：实测本机代价 4.9→0.4s（校准 §〇b-2：32 核 ffmpeg 8.1.2 视频链 ~3400fps，旧机 60-90s 口径被夸大）；仍改（正确性干净）。
2. **响度回执全链共享**（vtx/loudness_cache.py 新模块）：audio 阶段 LUFS/TP 按输入内容键（sha256）存 cache/audio/loudness_receipts.json，gates G2/G3 与 qc 优先读回执——正式轮 gates 日志「回执命中免测」生效；跨进程 fcntl.flock 互斥（M4 实质修复，P1-1 清单见 §四）。
3. **G1 批量化 + G10 口径修正**：G1 短窗 ebur128 逐 spawn → 分批（38 窗 4 批）单进程多输入 1.9s（校准推翻 v2「G1 是大头」归因：实测仅 3.5s）；真大头 G10 `-count_frames` 26.6s → `-count_packets` 0.12s（同值 16746，check_4k.sh 先例）。gates 合计 36.6→8.1s。
4. **QC 命中段免检**：按检查项记忆（总控裁定，阶段1 审查对抗攻击通过）——上轮该项 pass + final (size,mtime_ns) 不变 + 段 stat 不变才免检；✗ 项永远实测；--strict 全检。冷跑全检不受影响（每轮 cache 整删）。
5. **4K 发布链重做**（scripts/export_4k.py）：8 段并行 nvenc p4 + scale lanczos + concat -c copy，65.68s（vs x264 medium 133.8s，2.0×）；fps/帧数/时长前置校验 + 规格断言 14 项；x264 回退路径保留（--fallback-x264）。
6. **基准基建**（scripts/bench_cold.sh 生产化重做）：真实冷清理（rm -rf cache + out/receipt.json）、all --until video 消灭一条龙双跑、分步计时（/usr/bin/time + 逐行 epoch 打点 + [timing] 提取）、中位数表+波动告警、--with-4k 单列发布链、机器纪律（轮间 load<3）。
7. **文档收编**：runbook（耗时基准表更新 + 8 核→32C64G 订正 + 4K 命令段 R1/R5 更新 + 历史口径〔方案三前〕标注）、SKILL.md 冷跑预期（≈5 分钟 + 4K 另加 ~1 分钟）、DEV.md §一 性能基准定版条目 + 环境行订正。
