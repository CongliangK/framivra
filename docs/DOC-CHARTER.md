# Framivra 文档规则

本文件规定文档职责、写入边界与验证要求。程序行为不能靠改文档或门禁变更；CI 修改授权遵循 [AGENTS 写态红线](../AGENTS.md#写态红线)。

## 职责与入口

| 层 | 唯一职责与入口 |
| --- | --- |
| SKILL | [docs/skill/SKILL.md](skill/SKILL.md) 路由操作，references 解释机制，assets 提供模板；[templates](../templates/README.md) 承载工作流与开发范本，同属消费面，不另设一层。 |
| ARCHITECTURE | [ARCHITECTURE.md](ARCHITECTURE.md) 是系统边界与契约权威，不设平行契约。 |
| README | [根 README](../README.md) 面向初次使用者，只留项目介绍、安装与快速开始。 |
| docs | [DEV](DEV.md) 路由开发文档；guides 放操作指南，reference 放接口与结果语义，reports 留必要研究结论与证据。治理、生成入口保留其权威位置。 |

新内容优先并入已有主题，不为一次任务或每轮修复新建报告。普通主题名用小写 kebab；技能注册文件仍用 `SKILL.md`。

## 消费面

`docs/skill/` 与 `templates/**` 文档是执行者直接读取的内容；修改前说明受影响入口、用法与兼容性，并经消费面评审。改动由本仓维护者负责，修改仓库源件，不另改挂载副本。

挂载路径与链接清单以 `vt.py` 的 `MOUNT_LINKS` 为准。修改后须核对源文件存在、路径与实际挂载目标一致，并保留验证结果；无法访问真实挂载时明确报告未验，不把隔离夹具结果当作 live 验证。不得自动覆盖外仓链接、真实文件或目录；清理退役链接前必须确认其归属本仓。挂载检查只证路径与存在性，不证明文本正确或版本隔离。

## 写入与评审

文档由维护者评审；契约语义修改还须契约维护方同意并经过独立对抗审查，不得在实现或清理中单方面改写。纠错、搬移与压缩不能偷换契约。文档规则自身修订同样受这些边界约束。

实现后保留独立复审、适用验证与 PR 合入流程。评审须核对源码一致性、教程前置条件、消费文本质量及保留/删除的理由；这些判断不是机器门禁能替代的。

## 历史与证据

历史全文由 [清理前固定版本](https://github.com/CongliangK/framivra/tree/3d9e6622d5d06eecf55ffbe2075da1fa994f93f5) 保留，包含旧文档规则与归档目录；不是依赖会移动的分支链接。

不再被当前代码、测试、验收或有效契约消费的历史文档，经引用审计与独立复核后可从当前树移除，不必原位保留或另造归档入口。退役前确认固定版本可取回原文，并更新所有活引用。仍使用的契约、证据、许可证和未解决问题不能直接删除；活问题保留在 [known-issues](reference/known-issues.md)。

冻结证据保持原始字节与既有身份锚：整件或冻结节的哈希按原始字节复核，不作格式规范化；追加内容不得改动已冻结部分。更正或替换必须保留原件、原因与独立复核链，不能重录基线/哈希掩盖不一致。保留证据的可追溯性不等于保留所有历史过程稿。

## 单一事实来源

每一事实只有一个权威 home，其他页面链接而不重复维护。当前操作说明只描述当前行为；必要的演变依据归 Git 历史或已有研究/证据页。

- 组件清单由 manifest 与 registry 生成；修改 `app.json`、`plugin.json` 或 `plugins/registry.json` 后，必须重注 [catalog](catalog.md) 并通过文档门。重注是写操作：`python3 scripts/gen_manifest_catalog.py --inject docs/catalog.md`，不得手改生成区。
- 文档预算与数值政策只在 [预算快照](../scripts/doc_budget.snapshot.json)。修订须附实测依据并经评审；预算门只比较快照中的 measured 与阈值，不读取当前文档或执行 extract_cmd。现文字数必须另行测量，门绿不能证明现文符合预算。
- 冻结契约、许可证、验收夹具及证据源各保留自身权威 home；不得以清理文档为由改写它们或调整测试预期。

## 命令与验证

示例默认零写态，优先使用 bash 栅栏与 `--dry`/离线选项；确需写操作必须明确警示。例行 doctor 必须离线，裸 doctor 会 fetch 并写 `.git`。链接修复去掉 `--dry` 才会真正写入，执行前须核对目标仓与权限。

```bash
env VTX_DOCTOR_OFFLINE=1 python3 vt.py doctor
env python3 vt.py --fix-links --dry
```

[文档门](../scripts/doc_gates.sh) 的注册表与各 verifier 源码是检查范围的权威，不为清理文档删测试、放宽判据或改预算快照。聚合器要求全部注册 leaf 执行且通过，并核对注册、输出与头注计数。

`docs_smoke.sh` 扫描根 README、`apps/*/README.md`、`docs/**/*.md` 与 `templates/**/*.md`；docs 首层 `plans` 前缀是现存的历史豁免规则。它只对识别到的脚本执行 `--help` 或语法检查，不运行完整示例、不验证参数语义或业务效果；行内候选、SKIP 与覆盖边界以源码和实出结果为准。不得把该豁免当作放置当前文档的办法。

机器不覆盖散文/契约语义与教程适配。重复锚门只检查登记词族，预算门只检查快照；真实命令、挂载和媒体效果仍需对应环境中的实际验证。结果必须区分通过、失败、跳过与未运行，并指出未验证部分；门绿不等于全量正确。
