## 1. 目标与非目标

### 1.1 目标

1. **三大生成能力收编入仓**，各自独立顶层目录（asr/ tts/ imgen/，与 matting/ aroll/ 同级同风格），模块间零 import 依赖，与 vtx/ 渲染核心零耦合（vtx 包零改动）。
2. **ASR**：音频/视频 → 字级时间戳（Qwen3-ForcedAligner 路线）→ 文本规范化 → 断句聚合 → 30fps 帧级 `timeline.json subtitles[]` 合并（保护其他字段、写前备份）+ 独立 SRT。asr 模块自有轻量 sidecar（stdlib http.server，默认 18085，与 IME 输入法 sidecar 18081 解耦）。
3. **TTS**：IndexTTS-2.5 产线参数化收编（voice-ime/assets/voice_tts/ 的 27 窗硬编码 → spec.json 驱动），产物按 repack_voice.py 既有约定落位（`assets/voice_tts/final/<窗口ID>.wav`，48kHz/mono/pcm_s16le，时长=链帧/30+20ms），含 atempo 修正公式与峰值归一；edge-tts 作免 GPU 兜底档（建议纳入，见 §4.4）。
4. **imgen**：速创 API（api.wuyinkeji.com）内化（不依赖上游仓运行时），nano/gpt-image 两模型 + 异步提交轮询 + ffmpeg lanczos cover-crop 后处理，硬对接 matting 抠像链（`assets/bg/background_4k.png` 恰好 3840×2160 8-bit RGB PNG）与口播 1080p 消费；付费确认纪律内建。
5. **init 体系**：每模块幂等 init.sh，模型/依赖下载走国内渠道（ModelScope + 清华 PyPI，均已核实），**优先复用本机已有 GB 级资产**（探测+引用，不重复下载）；根 init.py 增三组探测项（幂等、--json 兼容）。
6. **config 接线**：config.example.json 更新 asr/tts + 新增 imgen；读取逻辑容错（旧 config.local.json 缺键 → 默认值，不要求重生成）。
7. **测试策略**：全部单元测试不依赖 GB 模型下载；真实冒烟按「本机资产探测得到则跑，否则打印跳过原因」；严禁对 live 工作区 voice-ime 原位写入。

### 1.2 非目标

- 不改动 vtx/ 任何文件（STAGES、composite ASS 生成、qc/audit 指标均原样消费）；不改 timeline.schema.json（subtitles[] 契约不变）。
- 不收编 IME 输入法仓任何代码进 vtx；不修改 IME 仓与其 sidecar（18081 保持原职责，video_tools 另起 18085）。

### 2.3 数据流：三模块如何服务 timeline.json 产线

1. **前置（人工/skill）**：`new_project.sh` 建项目骨架 `<项目>/{assets,gfx,cache,out}`；脚本定稿、口播录音或 TTS 占位。
2. **TTS 占位（正向）**：`tts/spec.py -t timeline.json` 从 voice 轨 `vt_<ID>` 事件链反推每窗预算 → spec.json（含文本，人工校对）→ `tts/gen` 合成 + atempo 贴预算 + 峰值归一 → `assets/voice_tts/final/<ID>.wav` → vtx `prepare/audio` 原样消费（与 make_subs.py+gen.py+repack 既有链同构，仅参数化）。
3. **实录替换（终版，既有链）**：用户按窗录音进 `assets/voice_takes/<ID>.wav` → 既有 `scripts/repack_voice.py` 替换（本仓已收编，零改动）。
4. **ASR 字幕（反向锚定）**：成片/口播音频（或实录 take）→ `asr/asr_cli.py timeline <音频> -t timeline.json`：sidecar 18085 转写+字级时间戳 → 规范化断句 → subtitles[] 就地合并（备份旧值进 cache/reports/）→ vtx `validate/audit` 复核（阅读速度 ≤9 字/s、行宽等）→ `video` 阶段 ASS 烧录。
5. **imgen 背景**：脚本阶段写 prompt → `imgen/gen`（0.1 元/张确认门）→ 原图即下（URL 2h 失效）→ cover-crop 成 `assets/bg/background_4k.png`（matting 链）或 1080p 变体（口播/gfx 底图）→ matting 全链合成 4K 成片。

### 3.2 CLI 接口签名

```
python3 asr/asr_cli.py sidecar start|stop|status|health     # start 拉起（后台、日志进 cache/reports/ 或 /tmp 小文件）
python3 asr/asr_cli.py transcribe <输入.wav|mp4|...> [--timestamps] [--json]
    # 默认纯文本；--timestamps 附 words[]（字级秒，3 位小数）
python3 asr/asr_cli.py srt <输入> -o <out.srt>
    [--limit 18] [--rate-cap 9] [--no-filler] [--t2s]
python3 asr/asr_cli.py timeline <输入> -t <timeline.json>
    [--offset-frames 0] [--min-dur-frames 18] [--gap-frames 2] [--dry-run] [--append]
python3 asr/asr_cli.py batch <目录或清单.txt> -o <输出目录>      # 逐文件 srt + 汇总 json 报告
```

- `<输入>` 音视频皆可（client 统一抽 16k mono wav 到 `cache/tmp/<runid>/`，退出即删）。
- `timeline` 子命令输出：subtitles[] 合并 + 摘要打印（窗数/字数/最快速率/最宽行），`--dry-run` 只打印 diff 不写。

### 3.3 sidecar 协议（默认 127.0.0.1:18085，可配）

| 端点 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/health` | GET | — | `{"status":"ok","model":"<路径或id>","aligner":"<路径或id 或 null>","port":18085,"version":1}` |
| `/warm` | POST | `{}` | `{"ok":true}`（模型预上 GPU） |
| `/transcribe` | POST | `{"audio":"<本地wav路径>","language":"Chinese","timestamps":true}` | `{"text":"…","words":[{"w":"字","s":0.833,"e":0.913},…],"duration_s":12.34}` |
| `/transcribe`（无 timestamps） | POST | `{"audio":…,"language":…}` | `{"text":"…"}` |

- 错误统一 `{"error":"中文可行动信息"}` + 4xx/5xx；音频不存在 400；`timestamps:true` 但 aligner 未加载 409（提示跑 init 下载 ForcedAligner）。
- **长音频：sidecar 直接透传任意时长输入，切分由库内部完成**（红队 P1-1 修正，v2）。qwen-asr 库已内建长音频处理：`MAX_FORCE_ALIGN_INPUT_SECONDS=180` / `MAX_ASR_INPUT_SECONDS=1200`（`inference/qwen3_asr.py:366`）是**自动分块目标值而非拒绝门槛**——`split_audio_into_chunks`（`inference/utils.py:246-281`）在目标点 ±5s 滑窗找低能量边界切分，保证样本级无损（各块拼接与原音频采样数严格相等、无重叠无缝隙），对齐结果经 `_offset_align_result` 偏移修正 + `_merge_align_results` 拼回（`qwen3_asr.py:420-449`）。sidecar **不做任何拒绝/预切分/偏移拼回**，client 同样零切分逻辑。
- 端口纪律：**18081 是 IME 输入法 sidecar 既有端口，绝不复用**；video_tools 默认 18085，`--port` / config `asr.base_url` 可改；启动前探测占用，冲突则报错退出（不静默换端口，防配置漂移）。
- **同卡共驻防护（R3/R6）**：sidecar 启动前探测 IME sidecar（18081 /health）是否存活——同驻则本 sidecar **默认降 0.6B 档**并打印提示（IME 1.7B + 本 1.7B + aligner 三者同驻 16GB 4080 必爆显存；用户可 `--model 1.7b` 显式覆盖并自担风险）。
- VRAM 换挡与空闲卸载（5 分钟可配）沿用 IME 实证策略；4080 16GB 下单独运行 1.7B+aligner 同驻约 6-8GB，余量充足。

### 3.4 text↔items 对齐（words[] 构造，sidecar 侧核心加工）

**问题**（红队 P1-2，v2 新增）：库 ForcedAligner 输出的 items 与 ASR 文本**不同构**，不能直接当 words[] 用（以下均经 `.venv-qwen-asr` 内源码核实）：

- items 只含 unicode L/N 类字符（字母/数字，**无标点**）——`is_kept_char` 只保留 `L*`/`N*` 类与撇号（`qwen3_forced_aligner.py:44-56`）；
- CJK 拆单字 token，但**拉丁/数字连续串为单 token**，且 `clean_token` 会变形（`qwen3_forced_aligner.py:59-60`）："3.14"→"314"、"Qwen3-ASR"→单 token "Qwen3ASR"（'.'/'-' 是**剥除**而非切断边界——连续串不因非 L/N 字符分裂）；
- 时间戳单位毫秒（`qwen3_forced_aligner.py:453` align 内计算；parse_timestamp 在 :239-262）——库**不做**转秒，round(ms/1000, 3) 转秒由 sidecar 承担；
- 而 ASR `text` 含标点、含原始形式（"3.14"带点）。**words[] 必须含标点且与 text 逐字对齐**，否则 §3.5 的断句行时间窗无从锚定。

**sidecar 侧 words[] 构造算法**（在 `/transcribe` 内完成，client 零参与）：

1. **双流规范化后贪心匹配**：text 流与 items 流各自做「大小写折叠 + 剥非 L/N 字符」得到可比序列；items 逐 token 在 text 流上贪心推进匹配——token 变形容认（"314" 可匹配 "3.14"，"Qwen3" 匹配 "Qwen3"；连续拉丁串允许跨 text 中的 `-`/`.`/空格吸收），CJK 单字一对一。匹配成功记录该 token 在 text 中的实际字符区间 [i, j) 与 items 时间 {s, e}（已转秒）。
2. **标点/非 L/N 字符不参与匹配**：text 中的标点与符号**继承时间锚 = 前一实字的 {s, e}（零宽锚）**——标点不占发音时间，行尾标点时间=末实字时间，保证「行时间窗=首字 s…末标点 e」不虚增时长。行首若出现标点由 §3.6 N1 删除。
3. **失配降级**：某区段贪心匹配失败（ASR 文本与对齐 items 数量/内容漂移，长音频跨块边界处最易发生）——该段字级时间戳缺失，行时间用**相邻已匹配区段线性插值兜底并告警**（响应附 `degraded_ranges: [[起,止],…]`）；整条全失配则 words=[]，客户端回退「整句均分」策略并显著告警。
4. **输出契约（sidecar 加工产物，明确区别于库原始输出）**：`words[]` = **单字粒度**（拉丁连续串拆回单字符、共享 token 时间窗）、**含标点**（零宽锚）、**单位秒、3 位小数**——即 §3.5 的直接输入。README 与 sidecar /health `version` 中注明「words 为 sidecar 加工格式，非 qwen-asr 原生 items（原生为 token 级、无标点、ms）」。

### 3.5 时间戳→帧→字幕聚合算法

输入：words[]（§3.4 契约：字级 `{w,s,e}` 秒，含标点零宽锚）；参数 fps=30（自 timeline `project.fps` 读取）、limit=18、rate_cap=9。

1. **字流锚定**：规范化（§3.6）只做「删除/替换」两类操作，在 (字, s, e) 序列上原位执行——口水词删除即删其字元与时间；标点替换保留时间锚（标点时间=前字 e）。保证任意输出行可回溯首末字时间。
2. **断句**：句末标点 `[。？！…]` 切句；句内超 limit 用 make_subs 同款贪心：`cut = max(rfind(句中标点, 0, limit))+1`，无句中标点则硬切并调 `latin_safe_cut`（回退到拉丁/数字词边界，防「Qwen3-ASR」被切成孤字行）。
3. **行时间窗**：行 `[start, end]` = 首字 s … 末字（含行尾标点，零宽锚）e。
4. **秒→帧**（左闭右开契约 [in, out)）：`in = floor(start*fps)`，`out = ceil(end*fps)`；最短 `min-dur-frames` 默认 **18 帧（=audit 过短线阈值 0.6s，stages.py:166 `d < 0.6`）**，不足则扩 out。
5. **相邻去重叠（自洽下限）**：`sub[i].out > sub[i+1].in` 时 `sub[i].out = max(sub[i].in + min_dur, sub[i+1].in - gap)`，gap 默认 2 帧——**去重叠不得把本行压到 in+min_dur 以下**；若受该下限约束仍与下一行冲突，则**保留重叠并告警**（audit 对重叠只 warn 不禁，validate 亦不禁止重叠——不人为截文本）。
6. **速率约束（与 audit 同口径）**：每行 `len(text) / ((out-in)/fps) ≤ 9`——**len(text) 含标点**（stages.py:161-163 audit 实测口径 `n = len(s["text"])`）；超限则在该行与下一行首字间隙内扩 out（有隙扩隙、无隙告警并接受——真实时间戳下极少触发，与 make_subs 的「分配式」不同，本链是「锚定式」）。
7. **越界夹取（保序丢弃）**：timeline 已知 duration_frames 时 in/out 夹入 [0, duration_frames]；**夹取后若 in >= out（整行落在时间轴外）则丢弃该行并告警**（validate 硬门 `0 <= in < out <= dur`，宁丢行不产出非法条目）。
8. 输出 subtitles[] 按 in 升序；同时产出审计摘要（每行速率/宽度分布）供人核。

### 5.3 ffmpeg 后处理（lanczos cover-crop，零新依赖）

速创 nano 2K 16:9 实出 ~2752×1536 ≠ 3840×2160，且 run_full_bg.sh 的 cv2.imread **直读逐像素合成、无 resize**，故必须后处理到精确尺寸：

```
ffmpeg -y -i <原始下载.png> \
  -vf "scale=<W>:<H>:force_original_aspect_ratio=increase:flags=lanczos,crop=<W>:<H>,format=rgb24" \
  -frames:v 1 <out.png>
```

- cover 语义：先等比缩放至**完全覆盖** W×H（放大用 lanczos，如 2752→3840），再中心 crop 到精确 W×H，最后 `format=rgb24` 压平 alpha/防 16-bit 与调色板 PNG（cv2.imread 要求 8-bit RGB）。
- **常态链路只降采样**：§5.2 联动矩阵保证源图 ≥ 目标尺寸（bg4k=4K 源、bg1080p=2K 源→1080p）；`postprocess` 子命令单独跑时若遇源 < 目标（需放大），打印插值倍数警告后照做（离线补救场景，用户自担画质）。
- 三种目标：3840×2160（bg4k）、1920×1080（bg1080p）、1080×1920（vertical，口播竖版）。
- 后处理后**像素级断言**：ffprobe/PIL 读 width/height/pix_fmt（或 mode=RGB），不符即失败删除——绝不让错尺寸图进 assets/bg/。

### 5.4 与 matting 抠像链 / 口播链对接方式

- **matting 链**：唯一接口 = `<项目>/assets/bg/background_4k.png` 恰好 3840×2160 8-bit RGB PNG（run_full_bg.sh `cv2.imread` 直读逐像素合成）。imgen 生成后自动 postprocess 到位并断言；matting 侧零改动。
- **口播/gfx 链**：1920×1080 / 1080×1920 变体供 timeline sources（`crop_center_scale`）与 gfx 底图使用；同样走 cover-crop 断言。
- 原图（API 直出）留档 `assets/imgen/`（可再处理），不入 cache/（cache 只放可再生中间物——API 原图不可再生，属资产）。
