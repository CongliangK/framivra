> 素材：微信传来的手机实拍口播 8.68s（1920×1080@30fps、260 帧、HEVC、含 AAC 原声）；宿舍场景（黄书架/梯子/蚊帐）、顶光、白 T 恤+金属框眼镜。

## 〇、总结论

| 维度 | 方案一：抠像 + AI 背景 + 合成 | 方案二：H3 R2V 视频直参重绘 |
|---|---|---|
| 效果 | ✅ 可用（发丝轻微硬边、镜片半透明正常、手臂少量残留，待人眼验收） | ✅ 优秀（身份/衣服图案保持、背景按要求重建、无可见瑕疵、质感近实拍） |
| 处理速度（5 分钟视频折算） | **≈10-15 分钟**（抠像 37.5s/260帧 + 背景生成 0.2 元 + 合成秒级） | **≈37 小时**（124 帧实测 44 分钟，≈510 倍实时） |
| 保真度 | 像素级保真（原帧原样保留） | 生成级保真（会重绘一切，含人脸——有身份漂移风险，需逐镜头抽检） |

| 时长匹配 | 任意长 | 单次 ≤124 帧（本机内存约束），长视频需分段+拼接，节奏按 24fps 对齐 |
| 成本 | 电费+0.2 元背景图 | 纯本地电费（44 分钟满载 GPU） |

## 一、方案一执行记录（全链路本地，vtx 兼容）

1. 抽帧：ffmpeg 260 帧 PNG（`frames/`）。素材实为 CFR（258/259 间隔=33ms，仅 1 帧 43.4ms），VFR 无影响；手机素材入库统一 `-fps_mode cfr -r 30` 归一化。
2. 首帧 mask：rembg(BiRefNet-general onnx 930MB，gh-proxy 下载) → `works/mask_f0000.png`，前景占比 34.6%。
3. 视频抠像：**MatAnyone**（权重 hf-mirror 下载，`works/run_matanyone.py` 自写 runner，坑：mask 必须二维 (H,W)、官方 erode/dilate 顺序是先 dilate 后 erode）。**260 帧仅 37.5 秒**（4080，~7fps）。5 分钟 1080p 视频约 7 分钟。
4. AI 背景：Slime nano 2K 16:9 两张（0.1 元/张）：A=暖调家庭工作室；B=带原图光照参考的现代办公室。
5. 合成：ffmpeg `[0][alpha]alphamerge → overlay`，alpha gblur 0.6 羽化，背景 cover-crop 1080p，原音轨直通。
   - 产物：`out/plan1_bgA.mp4`（暖工作室）、`out/plan1_bgB.mp4`（现代办公室）
6. 质检（AI 辅助初判）：整体成立；发丝边缘轻微硬边；眼镜镜片区域半透明（物理正确，但新背景会透出，特写镜头需注意）；手臂轮廓少量 alpha 残留。**待人工人眼验收**。
7. 已知改进空间（调研报告 §二）：接触阴影（20-30% 软投影）、rim light、背景色温对齐、发丝区局部加大羽化。

## 二、方案二执行记录（H3 R2V 视频直参）

**能力发现（重要资产）**：
- `MiniMaxH3ReferenceToVideo` 原生支持 `ref_videos.ref_video_0`（参考视频帧，24fps、2-15s）+ `ref_video_audios.ref_video_audio_0`（同号音轨），prompt 用 `<Video 1>` 引用；API 提交格式为**点号嵌套键**（batch_executor.py:171 的既有先例）。
- `MiniMaxH3AddGuide` 可把短片/音频锚定到生成视频任意帧位（本次未用，备选强锚定路线）。

**本次工作流**（`/tmp/wf_h3_r2v2.json` 结构已存本报告附录）：
- ref2va UNet + R2V 节点：ref_video_0=原视频前 124 帧（LoadImagesFromFolderKJ，stretch 到 1344×768）、**无音频参考**（按用户要求裁掉音频链路）；
- prompt：同一个人、同步说话动作，只换背景（浅暖灰墙+绿植+木架虚化），锁镜头；
- 输出 1344×768@24fps 124 帧（5.17s）→ 后处理 lanczos 拉伸 1920×1080 + mux 原声（`works/post_h3.sh`）。
- 产物：`out/plan2_h3.mp4`；原始输出 `~/AI/ComfyUI/output/bg_test_h3_r2v_videoref_00001_.mp4`

**音频链路简化的边界（用户问题实证）**：
- 可裁掉：音频参考输入、VAEDecodeAudio 节点、CreateVideo 的 audio（本次全部已裁）；
- 裁不掉：R2V 节点的 `audio_vae` 是必填输入（580MB 权重照常加载）；DiT 是音视频联合 latent，采样阶段的音频通道开销省不掉；
- 实际收益：主要是省去音频 VAE 解码与避免 H3 重合成语音（D2 铁律下我们本来就要用原录音）；速度收益占比小（瓶颈在视频 DiT）。

**性能实测**：
- 采样 20 步 × ~122s/步 ≈ 41 分钟（R2V 带视频参考比 I2V 慢：参考 token 跟随全部采样步；I2V 190f 之前实测 ~71s/步）；
- 全程 2646s 出 5.17s 成片，**≈510 倍实时**；5 分钟成片折算 ≈37 小时（比原 20h 估算更差，视频参考是额外开销）。

**失败教训（3 次才成功）**：
1. 190 帧 I2V：采样完成后 VAE 解码阶段 python 匿名内存 34GB 被 OOM-kill → **单次生成长度 ≤124 帧是本机（61GB RAM）硬约束**；
2. 一次整机级异常（用户确认与本项目无关）；一次 ComfyUI 进程被 SIGTERM（偶发）；
3. R2V videoref 运行时 ComfyUI 常驻 ~40GB RAM（smart-memory 把 TE 15GB+UNet 20GB stage 在内存），**跑 H3 前须关大内存常驻**（本次挂起了 ibus qwen-asr 6.3GB，经用户授权）。
4. 抖动细节：参考帧 30fps 直喂会被按 24fps 解释 → 动作/语速被拉慢 25%；**喂之前应把参考重采样到 24fps**（ffmpeg `fps=24`），本次未做（5.17s 短样本对评估画质无影响，量产时必须做）。

## 五、抠像升级实测（2026-08-24 补充，方案已拍板主线后执行）

**用户拍板**：H3 重绘否决（扩散改口型不可靠）；抠像+合成为核心路线。升级三件套同素材实测：

| 环节 | 旧 | 新 | 实测 |
|---|---|---|---|
| 首帧 mask | rembg BiRefNet onnx（锁 1024²） | **BiRefNet_HR-matting pth @2048²**（官方 handler 配方：正方形 resize+fp16+sigmoid） | `works/run_birefnet_hr.py`，秒级 |
| 视频抠像 | MatAnyone v1 | **MatAnyone2**（hydra 配置+load_weights 载 safetensors） | 260 帧 **62.5s**（~4.2fps，含收边；5min 视频≈15-20min） |
| 边缘 | gblur 0.6 | **guided filter radius=6**（cv2.ximgproc，原图引导） | 毫秒级/帧 |

**量化对比**（frame 130，`out/alpha_ma` vs `out/alpha_ma2`）：
- 帧间平均 alpha 变化：v1 0.00805 → v2 **0.00640（时间稳定性 +20%）**
- 全帧半透明像素：v1 49767 → v2raw 19447 / v2+gf 25885（v2 边界更干净，guided filter 适度回补发丝半透明）
- AI 视觉盲评（发丝区放大对比 `out/cmp_hair_side.png`）：v2 **明显更好**——v1 的发丝硬边/锯齿/绿残留、肩线绿溢出、镜框模糊在 v2 全部消失，"差距肉眼可见"。

**产物**：`out/plan1_v2_bgA.mp4`（升级版成片，同背景 A）、`out/shotV2_*.png`、`out/cmp_hair_side.png`（上下拼接发丝对比）、`out/cmp_full_v1/v2.png`（全帧绿幕检验）、`out/alpha_ma2/`（收边后 alpha）、`out/alpha_ma2_raw/`（未收边）。

**新踩坑（复用必读）**：
1. **MatAnyone2 光流模块启动时静默联网下载 ResNet18**（`~/.cache/torch/hub/checkpoints/resnet18-5c106cde.pth`）——被墙时表现为**进程假死**（GPU 占显存但 0% 利用率、线程全 futex 等待）。解法：手动预下载该文件（legacy tar 格式属正常，weights_only=False 可载）。
2. `MatAnyone2.from_pretrained()` 与新版 huggingface_hub hub_mixin 不兼容（缺 cfg 参数）——用官方 `hydra compose(eval_matanyone_config) + MatAnyone2(cfg) + load_weights(safetensors)` 路线（见 `works/run_matanyone2.py`）。
3. BiRefNet_HR 显存：fp32 短边 2048（即 2048×3648）会 OOM——照官方 handler 用**正方形 2048²+fp16**（~5GB 峰值）。
4. BiRefNet_HR 输出取 `model(x)[-1].sigmoid()`，不是 [-1][-1]+min-max。

## 七、M43 相机素材复测（2026-08-25，用户按拍摄指导首次实拍）

**素材**：松下系 M43 相机 4K UHD 3840×2160@29.97fps、44.5s（用户实拍测试，相机倒置拍摄需 180° 转正——桌面夹持方案落地前的临时做法）；宿舍场景、单顶光（打光方案尚未到位）、深色 T 恤、无眼镜。
**流程**：与 §五 升级三件套完全同款——hflip+vflip 转正 → 取 15s 起连续 260 帧（与旧口径等长）→ BiRefNet_HR@2048 首帧 mask（前景 15.5%）→ **MatAnyone2@2048**（4K 原生 OOM，降 2048 宽跑，260 帧 95.1s ≈2.7fps）→ guided filter 收边 → gblur 0.6 羽化 → 背景A alphamerge+overlay → 1080p 合成。
**产物**：`out/camtest_20260825/`（cam_bgA.mp4 / cmp_old_vs_new.jpg / alpha_2048 序列）。

**对比结论（vs §五 手机素材）**：
1. **帧间 alpha 稳定性 0.00167 vs 0.00640（≈3.8 倍提升）**——抠像时间稳定性显著更好（部分贡献来自本段动作幅度较小，量级差异可信）
2. 视觉对比（cmp_old_vs_new.jpg）：边缘残色/硬边基本消除、发丝过渡更自然、整体噪点更少（AI 目检结论）
3. 原始画质：旧手机素材欠曝严重（均亮度 42、暗部占 76%），新素材曝光健康（128/17%）——抠像质量差异的相当部分来自素材曝光改善
4. 遗留：暗部噪点仍可见（单顶光未打灯所致）、4K 原生抠像需 16G 显存以上或降 2048 跑（**工作流定档：抠像@2048，成片 1080p 下精度充裕**）
**下一步**：按既定打光方案（45° 主灯+卡纸辅光+关顶灯）后复拍，预期暗部噪点消除、alpha 稳定性进一步提高。

## 八、打光灯档位对比实测（2026-08-29，Ulanzi 灯到货后首拍）

**素材**：`~/视频/P1040015.MP4`（同款 M43 4K UHD 3840×2160@29.97fps、24.5s、相机正装无需转正）。用户口述：第 4s 与第 18s 为灯的两个亮度档位；截取 2-6s（Gear A）与 16-20s（Gear B）各 120 帧。
**流程**：与 §五/§七 升级三件套完全同款（抽帧@2048 → BiRefNet_HR 首帧 mask → MatAnyone2 → guided filter），GPU 空闲时 120 帧仅 **34.8s（≈3.4fps，比 §七 的 2.7fps 快）**。
**产物**：`out/lighttest_20260829/`（segA/B_raw 原切 4K + matt_segX_green/bgA 绿幕与背景A合成 1080p + cmp_*.png 对比图 + metrics.json + works/ 中间序列）。

**量化结论（metrics.json）**：

| 指标 | Gear A（4s 档，较暗） | Gear B（18s 档，较亮） | 判读 |
|---|---|---|---|
| 全帧均值 / >200 高光占比 | 119.9 / 5.2% | 126.0 / 10.5% | 均值几乎持平＝**相机自动曝光在补偿** |
| 静态背景区时域噪点（12帧 std，0-255） | **7.56** | **3.11** | **B 档噪点仅为 A 的 41%**——真实光输出的铁证 |
| alpha 帧间稳定性（MAD） | 1.368 | **0.857** | B 好 37%；噪点是 alpha 抖动的主因 |
| 半透明像素/帧 | 23284 | 22377 | 持平 |

**AI 视觉分析（4 项对比图盲评）**：发丝放大图 **B 明显更好**（A 有绿色镶边过渡带+过度平滑硬边，B 发丝保留完整）；肩部放大 B 略好（两者均干净）；全帧两图判定分裂——注意**视觉模型在压缩缩略图上判噪点不可靠**（暗画面噪点视觉上被 gamma 压缩，模型误判 A 更干净），以逐像素时域 std 实测为准。面部曝光 B 更健康（A 欠曝偏灰），白衣服两档均未爆（B 高光占比翻倍但纽扣/纹理仍可辨）。

**结论**：**更亮的 B 档全面胜出**（噪点 -59%、alpha 稳定性 +37%、发丝抠像肉眼可见更好、面部曝光更健康），且白衣服尚有高光余量——「买大不买小、低亮度运行」的选灯逻辑（D23）在实拍中兑现。**拍摄建议：用 B 档；如可能改手动曝光锁定，避免 AE 拉增益抵消打光收益**。8-11s 有一段比两档都亮的画面（均值 164-171），若为更高档位可再验一档。
**画质后期衔接**（对应调研 §二，链路已定待接入）：本素材为**原生 4K**——伪 4K 上传策略直接升级为原生 4K AVC 交付；残余噪点（B 档 3.11）由 `atadenoise+轻hqdn3d+cas≈0.45` 起步配方覆盖；抠像@2048→4K 交付时 alpha 上采样轻微软可用 cas 找补。可做实验：抠像前先轻降噪（时域自适应）能否把 alpha MAD 再压一档，代价是发丝细节损耗需 A/B 验证。
